## 2.1 Java开发环境搭建

**本课时对应知识点**：JDK、JRE、JVM 概念入门与下载安装。

**三者的包含关系**（面试高频）：

```
JDK（Java Development Kit  开发工具包）
 └── JRE（Java Runtime Environment  运行时环境）
      └── JVM（Java Virtual Machine  虚拟机）
```

- **JVM** —— 虚拟机，负责把字节码 `.class` 翻译成当前平台的机器码并执行。它是「跨平台」的实现者：不同操作系统有各自的 JVM 实现，磨平了系统差异。
- **JRE** = JVM + 核心类库（`java.lang`、`java.util`、`java.io` 等）。只想**运行**别人写好的 Java 程序，装 JRE 就够。
- **JDK** = JRE + 开发工具（`javac` 编译器、`java` 启动器、`jar` 打包、`javadoc` 文档、`jdb` 调试、`jconsole` 监控等）。要**写**Java 程序必须装 JDK。

**一句话记忆**：JDK 用来开发，JRE 用来运行，JVM 用来跨平台。

**版本怎么选（2026 年 9 月的现状）**。Java 每 6 个月发一个新版，每 2 年出一个 **LTS（长期支持版）**。LTS 序列是 Java 8 → 11 → 17 → 21 → **25**（2025 年 9 月发布，当前最新 LTS），下一个预计是 2027 年 9 月的 Java 29。

学习选择建议：

- **JDK 17 或 JDK 21** —— 最稳妥。企业存量项目最多，网上教程和框架文档基本以这两个版本为基准。本平台（知堂课堂）用的就是 Java 17。
- **JDK 25** —— 想用最新 LTS 可以选，但要注意生态工具的版本必须同步跟上（例如 Lombok 必须 1.18.40+，详见 JB1-3 龙目岛工具类）。
- **JDK 8** —— 已非常老，仅在维护老项目时才需要，不建议作为学习起点。

> **2026 年 9 月的一个许可变化值得知道**：随着 JDK 25 LTS 发布，Oracle 给 JDK 21 的一年宽限期到 2026 年 9 月结束。之后发布的 JDK 21 更新将转入 OTN 许可，商业生产使用需付费。想完全免费，可以用 **Eclipse Temurin（Adoptium）** 等 OpenJDK 发行版 —— 它们对 LTS 提供长期免费更新（Temurin 25 免费更新至少到 2031 年 9 月）。学习用途不受影响。

**下载与安装**：

- Oracle 官方：<https://www.oracle.com/java/technologies/downloads/>
- 免费开源发行版（推荐）：Eclipse Temurin <https://adoptium.net/>

Windows 安装注意三点：**安装路径不要有中文、不要有空格**（避免 `C:\Program Files` 这类带空格的路径引发脚本问题）；建议装到 `D:\develop\jdk17` 这类干净路径；JDK 9 之后安装包不再单独提供 JRE 目录，这是正常的。

验证安装成功（新开一个命令行窗口）：

```bash
java -version     # 打印运行时版本
javac -version    # 打印编译器版本
```

两条都有输出才算装好。只有 `java` 有输出而 `javac` 报「不是内部或外部命令」，说明你装的是 JRE 而不是 JDK，或者环境变量没配好。

## 2.2 Java环境变量配置

**本课时对应知识点**：为何配置 path 变量、如何配置 path 变量。

**为什么要配 path**。在命令行输入 `javac` 时，操作系统先在当前目录找这个可执行文件，找不到就依次去 `Path` 环境变量列出的每个目录里找。`javac.exe` 位于 JDK 的 `bin` 目录下，如果这个目录不在 `Path` 里，系统就报：

```
'javac' 不是内部或外部命令，也不是可运行的程序或批处理文件。
```

配置 `Path` 的本质就是**告诉系统去哪里找命令**，让你在任意目录下都能直接敲 `javac` 和 `java`，而不必每次写完整路径 `D:\develop\jdk17\bin\javac.exe`。

**Windows 配置步骤**：

1. `Win + R` 输入 `sysdm.cpl` → 高级 → 环境变量（也可以：此电脑右键 → 属性 → 高级系统设置）
2. 在**系统变量**区域找到 `Path` → 编辑 → 新建
3. 填入 JDK 的 bin 目录，例如 `D:\develop\jdk17\bin`
4. 一路确定，**关闭所有已打开的命令行窗口，重新开一个**再验证

**三个高频错误**：

- **改完不重开命令行**。环境变量在进程启动时读取一次，已打开的窗口读不到新值。IDEA 也一样，改完环境变量要重启 IDEA。
- **路径填到了 JDK 根目录**。必须精确到 `bin` 子目录 —— `javac.exe` 在 `bin` 里，不在根目录。
- **改的是用户变量而不是系统变量**（或反之）导致某些场景不生效。学习阶段配**系统变量**更省事。

**Linux / macOS 配置**（编辑 `~/.bashrc` 或 `~/.zshrc`）：

```bash
export JAVA_HOME=/usr/local/jdk17
export PATH=$JAVA_HOME/bin:$PATH
```

保存后执行 `source ~/.bashrc` 生效。

## 2.3 Java环境变量升级

**本课时对应知识点**：为何配置 JAVA_HOME 变量、如何配置 JAVA_HOME 变量。

**为什么还需要 JAVA_HOME**。`Path` 解决的是「命令能不能敲」，`JAVA_HOME` 解决的是「其他程序能不能找到 JDK」。Tomcat、Maven、Gradle、Elasticsearch、Nacos 这些工具启动时都会去读 `JAVA_HOME` 来定位 JDK。没配的话典型报错是：

```
JAVA_HOME environment variable is not set.
Error: JAVA_HOME is not defined correctly.
```

**第二个好处是便于换版本**。把 `Path` 写成引用形式后，将来升级 JDK 只需改 `JAVA_HOME` 一处：

1. 新建系统变量 `JAVA_HOME`，值为 JDK **根目录**（注意：不是 bin 目录），例如 `D:\develop\jdk17`
2. 把 `Path` 里原先写死的 `D:\develop\jdk17\bin` 改成 `%JAVA_HOME%\bin`

以后换成 JDK 21，只改 `JAVA_HOME` 的值指向新目录即可，`Path` 一个字都不用动。

**两个变量的分工总结**：

| 变量 | 值指向 | 作用 |
|---|---|---|
| `JAVA_HOME` | JDK **根目录** | 供 Maven / Tomcat 等第三方程序定位 JDK |
| `Path` | JDK 的 **bin 目录**（写作 `%JAVA_HOME%\bin`） | 供命令行直接识别 `java` / `javac` 命令 |

**验证**（Windows 命令行）：

```bash
echo %JAVA_HOME%      # 应打印 JDK 根目录
where javac           # 应打印 javac.exe 的完整路径
```

`JAVA_HOME` 的值末尾**不要加分号，也不要加反斜杠**，否则拼接出的路径会变成 `D:\develop\jdk17\\bin` 这类畸形值，有些工具能容忍，有些直接报错。

## 2.4 Java入门程序开发

**本课时对应知识点**：HelloWorld 程序、`javac.exe` 命令、`java.exe` 命令。

**第一步 写源码**。新建文件 `HelloWorld.java`（**文件名必须与 public 类名完全一致，包括大小写**），内容：

```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello World");
    }
}
```

**第二步 编译**。在文件所在目录打开命令行（技巧：在资源管理器地址栏直接输入 `cmd` 回车），执行：

```bash
javac HelloWorld.java
```

成功的标志是**没有任何输出**，并在同目录生成 `HelloWorld.class` —— 这就是字节码文件。命令行工具的惯例是「沉默即成功」。

**第三步 运行**：

```bash
java HelloWorld
```

输出 `Hello World`。

**关键细节**：`java` 后面跟的是**类名，不是文件名**，所以**不写 `.class` 后缀**。写成 `java HelloWorld.class` 会报 `ClassNotFoundException` —— 因为 JVM 会去找一个名叫 `HelloWorld.class` 的类。

**编译与运行两阶段图示**：

```
HelloWorld.java  --javac-->  HelloWorld.class  --java-->  Hello World
   （源码）        编译期        （字节码）        运行期      （输出）
```

**JDK 11 之后的简化写法**（单文件程序可以跳过编译，源码直接运行）：

```bash
java HelloWorld.java
```

方便做小练习，但它不会生成 `.class` 文件，且只适用于单文件。学习阶段建议先用 `javac` + `java` 两步走，把编译和运行两个阶段分清楚。

**初学者最常见的四个报错**：

| 报错 | 原因 |
|---|---|
| `找不到文件 HelloWorld.java` | 命令行当前目录不对，或文件真名是 `HelloWorld.java.txt`（没开显示扩展名） |
| `类 HelloWorld 是公共的, 应在名为 HelloWorld.java 的文件中声明` | 文件名与 public 类名不一致（含大小写） |
| `错误: 找不到或无法加载主类` | 运行时多写了 `.class` 后缀，或类名拼错，或不在 `.class` 所在目录 |
| `找不到主方法` | `main` 方法签名写错，少了 `static`、`String[]` 写错、`main` 拼错 |

## 2.5 Java入门程序详解

**本课时对应知识点**：类、`main()` 方法、输出语句、代码通用要求与格式。

把 HelloWorld 逐层拆开：

```java
public class HelloWorld {                              // ① 类声明
    public static void main(String[] args) {           // ② 主方法
        System.out.println("Hello World");             // ③ 输出语句
    }
}
```

**① `public class HelloWorld`** —— 类声明。`class` 是定义类的关键字；`public` 表示公开访问权限。**一个 `.java` 文件里最多只能有一个 `public` 类，且必须与文件名同名**。类名用**大驼峰**（每个单词首字母大写，如 `HelloWorld`、`UserService`）。

**② `public static void main(String[] args)`** —— 程序入口，JVM 启动时固定找这个签名的方法。逐词解释：

- `public` —— 必须公开，否则 JVM 在类外部无法调用它。
- `static` —— 静态方法，属于类而不属于对象。JVM 启动时还没有任何对象存在，只能通过类直接调用。
- `void` —— 无返回值。返回给 JVM 没有意义。
- `main` —— 固定名称，**不能改**。改成 `Main` 就找不到入口了。
- `String[] args` —— 命令行参数数组。执行 `java HelloWorld a b c` 时，`args` 就是 `["a","b","c"]`。参数名 `args` 可以改（写成 `String[] x` 也行），但类型 `String[]` 不能改。`String args[]` 和 `String... args` 也是合法写法。

**③ `System.out.println("Hello World")`** —— 标准输出。`System` 是 `java.lang` 包下的系统类，`out` 是它的静态字段（标准输出流），`println` 是打印并换行（print line）。字符串用**英文双引号**包裹；语句以**英文分号**结尾。

**代码通用要求与格式**：

1. **严格区分大小写** —— `String` 与 `string` 是两回事，`Main` 不是 `main`。
2. **所有符号必须是英文半角** —— 中文引号 `“”`、中文分号 `；`、中文括号 `（）` 是初学者最高频的编译错误来源，而报错信息往往指向让人困惑的位置。
3. **每条语句以 `;` 结尾**。
4. **`{}` 必须成对**，缩进用 4 个空格（或 Tab，但项目内要统一）。
5. **一层大括号缩进一级**，让代码结构一眼可见。
6. **命名规范**：类名大驼峰 `HelloWorld`；方法名和变量名小驼峰 `getUserName`；常量全大写下划线分隔 `MAX_SIZE`；包名全小写 `com.mdkj.service`。

**关于注释**（详见 JB1-2 文档化编程思想）：

```java
// 单行注释
/* 多行注释 */
/** 文档注释，可用 javadoc 提取成 HTML */
```

**程序执行的完整链路**（把本单元串起来）：

```
写 .java 源码
   ↓ javac（编译期：检查语法、类型，生成字节码）
生成 .class 字节码
   ↓ java（运行期：类加载 → 字节码校验 → 解释/JIT 编译 → 执行）
JVM 找到 main() 方法，逐行执行
   ↓
控制台输出结果
```

理解「编译期」和「运行期」的分界非常重要 —— 后面学到的很多概念都要按这条线区分：语法错误、类型不匹配属于编译期问题；空指针、数组越界、类型转换失败属于运行期问题（见 JB1-4 异常例外）。
