## 1.1 万物皆为对象

**本课时对应知识点**：万事万物皆对象、对象具有唯一性、对象可以具有属性和方法。

**「万物皆对象」是什么意思**。现实世界中一切可以被指认的实体都是对象：一个人、一辆车、一本书、一个订单、一次点击。面向对象编程的第一步，就是**用对象来映射现实世界**，而不是把现实世界拆解成一堆步骤。

**对象的两个组成部分**：

| 组成 | 现实含义 | 代码体现 |
|---|---|---|
| **属性**（Field / Property） | 对象「**有什么**」，静态特征 | 成员变量 |
| **方法**（Method） | 对象「**能做什么**」，动态行为 | 成员方法 |

以「学员」为例：

```
学员对象
├── 属性：姓名、年龄、学号、已购课程
└── 方法：登录、购买课程、观看视频、发弹幕
```

用代码表达：

```java
public class Student {
    // 属性：有什么
    private String name;
    private int age;
    private String studentNo;

    // 方法：能做什么
    public void login() { ... }
    public void buyCourse(Long courseId) { ... }
    public void watchVideo(Long episodeId) { ... }
}
```

**对象的唯一性（本课时的重要概念）**。每个对象都是独立的个体，即使属性完全相同，也是**两个不同的对象**：

```java
Student s1 = new Student("张三", 20);
Student s2 = new Student("张三", 20);

System.out.println(s1 == s2);        // false  ← 两个不同的对象
System.out.println(s1.equals(s2));   // false（未重写 equals 时）
```

**唯一性的三层含义**：

1. **内存地址唯一** —— 每次 `new` 都在堆中开辟新空间，地址不同（见 JB1-2 运行时数据区域）
2. **身份独立** —— 修改 `s1` 的属性不影响 `s2`
3. **现实对应** —— 就像世界上有两个叫「张三」的人，他们是不同的人

```java
s1.setAge(21);
System.out.println(s2.getAge());     // 20  ← s2 不受影响
```

**「类」与「对象」的关系（最核心的一对概念）**：

| | 类（Class） | 对象（Object / Instance） |
|---|---|---|
| 定位 | **模板 / 设计图** | **实例 / 具体产品** |
| 数量 | 一个 | 可以创建无数个 |
| 存在时机 | 编译期就存在 | 运行时 `new` 出来 |
| 类比 | 「学员」这个概念、户口本模板 | 张三、李四这两个具体的人 |
| 内存 | 方法区（类信息） | 堆 |

```java
// Student 是类（模板）
public class Student { ... }

// s1、s2 是对象（实例）
Student s1 = new Student();
Student s2 = new Student();
```

**更多类比**：图纸 → 房子；月饼模具 → 月饼；简历模板 → 填好的简历。**先有类，才能造对象**。

**Java 中一切皆对象吗？** 严格说**不完全是** —— 8 种基本类型（int、double、char……）**不是对象**，它们是为了性能而保留的特例。这也正是包装类存在的原因（见 JB1-2 装箱和拆箱过程）。除此之外，类、数组、字符串、异常、甚至 `Class` 本身都是对象。

## 1.2 面向对象编程

**本课时对应知识点**：考虑问题时以具体的对象为单位，考虑其属性和方法，而非具体的实现流程。

**面向过程 vs 面向对象（本课时的核心对比）**：

| | 面向过程（POP） | 面向对象（OOP） |
|---|---|---|
| 核心单位 | **函数 / 过程** | **对象 / 类** |
| 思考方式 | 「**第一步做什么，第二步做什么**」 | 「**谁来做，他有什么能力**」 |
| 数据与行为 | **分离** —— 数据是数据，函数是函数 | **绑定** —— 数据和操作它的方法在一起 |
| 代表语言 | C、Pascal | Java、C++、C# |
| 优势 | 流程直观、性能高、适合小程序 | 易扩展、易维护、适合大项目 |

**用同一个需求对比：计算课程订单总价**

**面向过程的思路**（关注步骤）：

```java
// 数据是散落的
double[] prices = {100, 200, 300};
int[] counts = {1, 2, 1};

// 函数独立于数据
public static double calcTotal(double[] prices, int[] counts) {
    double total = 0;
    for (int i = 0; i < prices.length; i++) {
        total += prices[i] * counts[i];
    }
    return total;
}
```

**问题**：数据和函数分离。如果要加「折扣」，得改函数签名、改所有调用处；如果有十个函数都操作这组数据，任何一处修改都可能引发连锁反应。

**面向对象的思路**（关注角色和职责）：

```java
// 订单项：自己知道自己的小计怎么算
class OrderItem {
    private Course course;
    private int count;

    public BigDecimal subtotal() {
        return course.getPrice().multiply(BigDecimal.valueOf(count));
    }
}

// 订单：自己知道自己的总价怎么算
class Order {
    private List<OrderItem> items;
    private Coupon coupon;

    public BigDecimal total() {
        BigDecimal sum = items.stream()
            .map(OrderItem::subtotal)
            .reduce(BigDecimal.ZERO, BigDecimal::add);
        return coupon != null ? coupon.apply(sum) : sum;
    }
}
```

**优势**：数据和行为封装在一起。加折扣只需改 `Coupon` 类，`Order` 和 `OrderItem` 完全不用动。**修改的影响范围被限制在对象内部**。

**面向对象的三大特性（贯穿本课程后续单元）**：

| 特性 | 含义 | 对应单元 |
|---|---|---|
| **封装**（Encapsulation） | 隐藏内部细节，只暴露必要接口 | 第 2 单元 |
| **继承**（Inheritance） | 子类复用父类的属性和方法 | 第 3 单元 |
| **多态**（Polymorphism） | 同一个引用在不同情况下表现不同行为 | 第 4 单元 |

**面向对象的思考步骤（实用方法）**：

1. **找名词** —— 从需求描述中找出所有名词，它们是候选的**类**
2. **找形容词** —— 描述名词特征的词，它们是**属性**
3. **找动词** —— 名词能做的事，它们是**方法**
4. **理关系** —— 类之间是「是一个」（继承）还是「有一个」（组合）

**实战演练**。需求：「学员可以购买课程，课程包含多个章节，每个章节包含多个课时」

```
找名词 → 学员(Student)、课程(Course)、章节(Season)、课时(Episode)、订单(Order)
找属性 → 课程有标题、价格、封面；课时有标题、视频地址、时长
找方法 → 学员能购买课程；课程能获取章节列表
理关系 → 课程「有一个」章节列表（组合）
         VIP学员「是一个」学员（继承）
```

这正是本平台（知堂课堂）的实际建模方式 —— `course` → `season` → `episode` 三级结构。

**面向对象不是万能的**。简单的工具方法（如数学计算、字符串处理）用静态方法就够了，硬套对象反而繁琐 —— `Math.abs()` 就是典型的面向过程风格，但它非常合适。**判断标准是：这个东西有没有「状态」需要维护**。

## 1.3 抽象编程思想

**本课时对应知识点**：抽选出一些我们比较关注的属性和方法的思想过程。

**什么是抽象**。抽象（Abstraction）是**从具体事物中提取出我们关心的特征，忽略不关心的部分**的思维过程。「抽」是抽取，「象」是特征。

**关键认知：抽象是有立场的** —— 抽取什么取决于你的业务场景，同一个现实对象在不同系统里的抽象结果完全不同。

**同一个「人」在不同系统中的抽象**：

```java
// 在教育平台里，关心学习相关的特征
class Student {
    String name;
    String studentNo;
    List<Course> purchasedCourses;
    int watchDuration;

    void watchVideo() { }
    void submitHomework() { }
}

// 在医院系统里，关心健康相关的特征
class Patient {
    String name;
    String medicalRecordNo;
    String bloodType;
    List<Diagnosis> history;

    void register() { }
    void takeMedicine() { }
}

// 在银行系统里，关心资金相关的特征
class Customer {
    String name;
    String idCard;
    BigDecimal balance;
    int creditScore;

    void transfer() { }
    void applyLoan() { }
}
```

**三个类描述的可能是同一个人**，但抽取的属性和方法完全不同。教育平台不关心血型，医院不关心信用分。**抽象的价值就在于「舍弃无关信息」** —— 如果什么都往类里塞，类会变成一个无法维护的怪物（上帝类）。

**抽象的四个步骤**：

1. **确定场景** —— 明确这个系统要解决什么问题
2. **识别对象** —— 找出场景中的关键实体
3. **提取特征** —— 只保留与业务相关的属性和方法
4. **持续调整** —— 需求变化时重新审视抽象是否合适

**抽象的层次（从具体到一般）**：

```
                 动物 Animal              ← 最抽象
                /            \
            狗 Dog          猫 Cat        ← 较抽象
           /      \
    柯基 Corgi   金毛 Golden               ← 较具体
        |
   我家那只叫豆豆的柯基                     ← 最具体（对象实例）
```

**层次越高，共性越多、细节越少、适用范围越广**。这个层次结构在代码里就体现为继承体系（第 3 单元）和抽象类 / 接口（第 5 单元）。

**抽象的两种典型产物**：

**① 抽象类** —— 提取共同的属性和部分实现，留下未确定的行为让子类完成：

```java
abstract class Animal {
    protected String name;          // 共同属性
    public void eat() {             // 共同实现
        System.out.println(name + "在吃东西");
    }
    public abstract void speak();   // 抽象方法：每种动物叫声不同，交给子类
}
```

**② 接口** —— 只提取「能做什么」，完全不管「怎么做」：

```java
interface Flyable {
    void fly();
}
// 鸟能飞，飞机也能飞，但它们的实现方式毫无关系
```

这两者的详细区别见第 5 单元「特殊之抽象类」和「特殊之接口类」。

**抽象的两个常见误区**：

**① 过度抽象**。为了「以后可能扩展」而设计出七八层继承、十几个接口，结果每加一个功能要改十个文件。**记住 YAGNI 原则（You Aren't Gonna Need It）—— 不要为想象中的需求做设计**。抽象应当来自真实的重复，而不是对未来的猜测。

**② 抽象不足**。所有逻辑堆在一个类里，几千行代码什么都干（上帝类）。典型信号是：类名叫 `Manager`、`Helper`、`Util` 却塞满了业务逻辑。

**判断抽象是否合适的三个信号**：

- ✅ **好的抽象**：新增一个同类需求时，只需新增一个类，不用改现有代码（开闭原则）
- ❌ **抽象不足**：改一个小功能要在多处重复修改
- ❌ **过度抽象**：为了看懂一个简单功能要跳转五六层调用

**抽象与三大特性的关系**：

```
抽象（思维方法）
  ├── 封装 —— 抽象出「哪些该暴露、哪些该隐藏」
  ├── 继承 —— 抽象出「不同类之间的共性」
  └── 多态 —— 抽象出「统一的调用方式，不同的具体行为」
```

**抽象是面向对象的思想内核，三大特性是实现抽象的语言工具**。理解了这一层，后面五个单元学的就不是孤立的语法，而是同一套思想的不同表达。
