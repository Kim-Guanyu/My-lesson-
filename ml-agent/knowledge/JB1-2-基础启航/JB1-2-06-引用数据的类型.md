## 6.1 引用类型字符串

**本课时对应知识点**：字符串完整声明格式、简易声明格式、底层数据结构。

**String 是引用类型，不是基本类型**。Java 的 8 种基本类型是 byte/short/int/long/float/double/char/boolean，`String` 不在其中 —— 它是 `java.lang` 包下的一个**类**。

**两种声明方式**：

```java
// ① 简易声明（字面量方式）—— 推荐
String s1 = "hello";

// ② 完整声明（构造器方式）—— 不推荐
String s2 = new String("hello");
```

**两者的区别（面试高频）**：

```java
String s1 = "hello";
String s2 = "hello";
String s3 = new String("hello");

System.out.println(s1 == s2);        // true  ← 指向同一个对象
System.out.println(s1 == s3);        // false ← 不同对象
System.out.println(s1.equals(s3));   // true  ← 内容相同
```

**原因是字符串常量池**：

- **字面量方式**：JVM 先去**字符串常量池**（String Pool）查找是否已有 `"hello"`。有就直接返回它的引用，没有就创建并放入池中。所以 `s1` 和 `s2` 指向的是**同一个对象**。
- **new 方式**：**强制在堆中创建一个新对象**，无论常量池里有没有。所以 `s3` 是一个全新对象，`==` 比较必然是 false。

`new String("hello")` 实际上可能创建**两个对象**：常量池中的 `"hello"`（如果之前没有）+ 堆中的新对象。这就是不推荐 new 方式的原因 —— 白白浪费内存。

**`intern()` 方法**：手动把字符串放入常量池，并返回池中的引用：

```java
String s3 = new String("hello");
System.out.println(s1 == s3.intern());   // true
```

**String 的底层数据结构**：

- **JDK 8 及以前**：`private final char value[];` —— 用 char 数组存储，每个字符固定占 2 字节
- **JDK 9 及以后**：`private final byte[] value;` + `private final byte coder;` —— 改用 byte 数组，并用 `coder` 标记编码方式（LATIN1 或 UTF16）

**JDK 9 为什么要改**（这是著名的「Compact Strings」优化）：统计发现大多数字符串只包含拉丁字符（英文、数字、符号），用 char 数组存储时每个字符浪费 1 字节。改成 byte 数组后，纯拉丁字符串**内存占用直接减半**，显著降低了堆内存压力和 GC 频率。

**String 的三大特性**：

**① 不可变（Immutable）** —— 这是 String 最重要的特性。`value` 数组被 `private final` 修饰，且 String 类本身是 `final` 的（不能被继承）。

```java
String s = "hello";
s = s + " world";       // 不是修改原字符串，而是创建了一个新的 String 对象
```

**不可变的好处**：可以安全地在多线程间共享（天然线程安全）；可以缓存 hashCode（所以 String 做 HashMap 的 key 效率很高）；可以放进常量池复用；作为参数传递时不用担心被方法内部修改。

**代价**：频繁修改字符串会产生大量临时对象 —— 所以循环拼接必须用 `StringBuilder`（见 JB1-4 字符拼接工具）。

**② final 类** —— 不可被继承，保证了行为的确定性和安全性。

**③ 实现了 CharSequence 接口** —— 与 `StringBuilder`、`StringBuffer` 同属一个体系。

**字符串常量池的位置变迁**（面试常问）：JDK 6 及以前在**方法区（永久代 PermGen）**；**JDK 7 移到了堆中**；JDK 8 移除永久代改用元空间（Metaspace），但**字符串常量池仍在堆中**。移到堆中的原因是永久代空间有限且回收效率低，容易导致 `OutOfMemoryError: PermGen space`。

**编译期常量拼接的优化**：

```java
String s1 = "hel" + "lo";        // 编译期就合并成 "hello"，直接进常量池
String s2 = "hello";
System.out.println(s1 == s2);    // true！

String h = "hel";
String s3 = h + "lo";            // 变量参与，运行期用 StringBuilder 拼接，产生新对象
System.out.println(s3 == s2);    // false

final String h2 = "hel";
String s4 = h2 + "lo";           // final 变量是编译期常量，仍会被优化
System.out.println(s4 == s2);    // true
```

## 6.2 字符串编程接口

**本课时对应知识点**：API 概念、API 文档概念、API 文档的使用方法、字符串常用 API。

**什么是 API**。API = Application Programming Interface（应用程序编程接口）。通俗讲就是**别人写好的、供你调用的方法清单**。你不需要知道 `length()` 内部怎么实现，只需要知道「调用它能得到字符串长度」。

**什么是 API 文档**。JDK 提供了几千个类、几万个方法，不可能全部记住。API 文档就是这些类和方法的**说明书**，记录每个方法的作用、参数、返回值、可能抛出的异常。它由 javadoc 工具从源码注释生成（见本课程第 1 单元）。

**API 文档的使用方法**：

- **在线查阅**：<https://docs.oracle.com/en/java/javase/17/docs/api/>（把 17 换成你的 JDK 版本）
- **IDEA 内查看**：光标停在方法名上按 `Ctrl + Q` 查看文档；`Ctrl + B` 跳转到源码
- **查阅步骤**：① 确定类属于哪个包 → ② 找到类 → ③ 在方法列表中找目标方法 → ④ 看参数、返回值、说明和示例

**String 常用 API 分类速查**：

**获取信息类**：

```java
String s = "Hello World";
s.length();                    // 11    长度
s.charAt(0);                   // 'H'   取指定位置字符
s.indexOf("o");                // 4     首次出现的下标，找不到返回 -1
s.lastIndexOf("o");            // 7     最后一次出现的下标
s.isEmpty();                   // false 长度是否为 0
s.isBlank();                   // false 是否为空或全空白（JDK 11+）
```

**判断类**：

```java
s.equals("Hello World");       // true   内容比较（区分大小写）
s.equalsIgnoreCase("HELLO WORLD");  // true  忽略大小写
s.contains("World");           // true   是否包含
s.startsWith("Hello");         // true   是否以...开头
s.endsWith("World");           // true   是否以...结尾
s.matches("[A-Za-z ]+");       // true   是否匹配正则
```

**转换类（注意：都返回新字符串，不修改原字符串）**：

```java
s.toUpperCase();               // "HELLO WORLD"
s.toLowerCase();               // "hello world"
s.trim();                      // 去除首尾空格
s.strip();                     // 去除首尾空白（JDK 11+，能处理 Unicode 空白）
s.substring(6);                // "World"      从下标 6 到末尾
s.substring(0, 5);             // "Hello"      [0,5) 左闭右开
s.replace("World", "Java");    // "Hello Java" 替换所有匹配
s.concat("!");                 // "Hello World!" 拼接
s.repeat(3);                   // 重复 3 次（JDK 11+）
s.split(" ");                  // ["Hello","World"] 按分隔符切分
String.join("-", "a","b","c"); // "a-b-c"      用分隔符连接
s.toCharArray();               // 转成 char 数组
String.valueOf(123);           // "123"        任意类型转字符串
```

**关键提醒：String 的所有「修改」方法都返回新字符串，原字符串永远不变**：

```java
String s = "hello";
s.toUpperCase();               // ❌ 没有效果！返回值被丢弃了
System.out.println(s);         // 还是 "hello"

s = s.toUpperCase();           // ✅ 必须接收返回值
System.out.println(s);         // "HELLO"
```

这是初学者最高频的错误之一，根源就是没理解 String 的不可变性。

**`substring` 的下标规则**：左闭右开 `[start, end)`，包含 start 不包含 end。`substring(0, 5)` 取的是下标 0、1、2、3、4 共 5 个字符。下标越界会抛 `StringIndexOutOfBoundsException`。

**遍历字符串的三种方式**：

```java
String s = "Hello";

// ① for + charAt
for (int i = 0; i < s.length(); i++) {
    System.out.println(s.charAt(i));
}

// ② 转成 char 数组后增强 for
for (char c : s.toCharArray()) {
    System.out.println(c);
}

// ③ chars() 流式处理（JDK 8+）
s.chars().forEach(c -> System.out.println((char) c));
```

## 6.3 正则表达式专题

**本课时对应知识点**：正则表达式（RE）的意义、正则字符、`matches()`、`replaceAll()`、`split()`。

**正则表达式是什么**。用一串特殊字符描述**字符串的匹配规则**。它的意义在于：用一行表达式替代几十行的手写校验逻辑。

```java
// ❌ 手写校验手机号：判断长度、判断每位是数字、判断开头是 1……
// ✅ 正则一行搞定
boolean ok = phone.matches("1[3-9]\\d{9}");
```

**常用正则字符**：

| 符号 | 含义 | 示例 |
|---|---|---|
| `.` | 任意一个字符（除换行） | `a.c` 匹配 `abc`、`a1c` |
| `\d` | 数字 `[0-9]` | `\d{3}` 匹配三位数字 |
| `\D` | 非数字 | |
| `\w` | 单词字符 `[a-zA-Z0-9_]` | |
| `\W` | 非单词字符 | |
| `\s` | 空白字符（空格、Tab、换行） | |
| `\S` | 非空白 | |
| `[abc]` | 括号中任意一个字符 | |
| `[^abc]` | 除了 abc 之外的字符 | |
| `[a-z]` | 范围内任意字符 | |
| `\|` | 或 | `cat\|dog` |
| `()` | 分组 | |

**数量词（量词）**：

| 符号 | 含义 |
|---|---|
| `*` | 0 次或多次 |
| `+` | 1 次或多次 |
| `?` | 0 次或 1 次 |
| `{n}` | 恰好 n 次 |
| `{n,}` | 至少 n 次 |
| `{n,m}` | n 到 m 次 |

**边界符**：`^` 开头、`$` 结尾、`\b` 单词边界。

> ⚠️ **Java 中反斜杠要写两遍**。因为 `\` 在 Java 字符串里本身是转义字符，正则的 `\d` 在 Java 代码中必须写成 `"\\d"`。这是初学者最容易懵的地方。

**三个核心方法**：

**① `matches()` —— 整体匹配校验**

```java
"13812345678".matches("1[3-9]\\d{9}");        // true   手机号
"abc123".matches("[a-z]+\\d+");               // true
"abc".matches("[a-z]");                       // false  必须整体匹配，不是部分匹配
```

**注意**：`matches()` 要求**整个字符串完全匹配**，相当于自动在两端加了 `^` 和 `$`。

**② `replaceAll()` —— 按正则替换**

```java
"a1b2c3".replaceAll("\\d", "*");              // "a*b*c*"   所有数字换成 *
"hello   world".replaceAll("\\s+", " ");      // "hello world"  多个空白压成一个
"2026-09-09".replaceAll("-", "/");            // "2026/09/09"
```

**③ `split()` —— 按正则切分**

```java
"a,b,c".split(",");                    // ["a","b","c"]
"a1b22c333d".split("\\d+");            // ["a","b","c","d"]  按连续数字切
"a,b,,c".split(",");                   // ["a","b","","c"]   保留中间空串
"a,b,c,,".split(",");                  // ["a","b","c"]      末尾空串被丢弃
"a,b,c,,".split(",", -1);              // ["a","b","c","",""] 加 limit=-1 保留
```

**常用正则实例（可直接用于项目）**：

```java
// 手机号（中国大陆）
"1[3-9]\\d{9}"

// 邮箱
"\\w+@\\w+\\.[a-z]{2,6}"

// 身份证（18位）
"\\d{17}[\\dXx]"

// 用户名：字母开头，4-16位字母数字下划线
"[a-zA-Z]\\w{3,15}"

// 密码：至少8位，包含大小写字母和数字
"^(?=.*[a-z])(?=.*[A-Z])(?=.*\\d).{8,}$"

// IP 地址（简化版）
"(\\d{1,3}\\.){3}\\d{1,3}"

// 日期 yyyy-MM-dd
"\\d{4}-\\d{2}-\\d{2}"

// 中文字符
"[\\u4e00-\\u9fa5]+"
```

**Pattern 与 Matcher（需要提取内容时用）**：

```java
import java.util.regex.*;

Pattern p = Pattern.compile("(\\d{4})-(\\d{2})-(\\d{2})");
Matcher m = p.matcher("今天是 2026-09-09 星期三");
if (m.find()) {
    System.out.println(m.group());    // 2026-09-09   整体
    System.out.println(m.group(1));   // 2026         第1组
    System.out.println(m.group(2));   // 09           第2组
    System.out.println(m.group(3));   // 09           第3组
}
```

**性能建议**：`Pattern.compile()` 有编译开销，如果同一个正则要反复使用（比如在循环里或高频接口中），应把 `Pattern` 提取成 `static final` 常量复用，不要每次都编译。

**正则的实践建议**：能用简单字符串方法解决的就不要用正则（`contains()` 比 `matches(".*x.*")` 清晰得多）；复杂正则一定要写注释说明意图；用在线工具（regex101.com）测试和调试；小心「灾难性回溯」—— 嵌套量词如 `(a+)+` 遇到特定输入会导致 CPU 飙升，这是一种真实的拒绝服务风险。

## 6.4 运行时数据区域

**本课时对应知识点**：栈、堆、内存地址、基本类型和引用类型在运行时数据区中的分布。

**JVM 运行时数据区的五大区域**：

| 区域 | 线程私有/共享 | 存什么 |
|---|---|---|
| **虚拟机栈（Stack）** | 私有 | 局部变量、方法调用的栈帧 |
| **堆（Heap）** | **共享** | **所有对象实例和数组** |
| **方法区 / 元空间** | 共享 | 类信息、静态变量、常量池 |
| 程序计数器 | 私有 | 当前执行到的字节码行号 |
| 本地方法栈 | 私有 | native 方法的调用 |

**本课时重点是栈和堆**。

**栈（Stack）的特点**：先进后出；每调用一个方法就压入一个**栈帧**，方法结束栈帧弹出，其中的局部变量随即销毁；空间小、速度快、自动管理，无需 GC。

**堆（Heap）的特点**：所有 `new` 出来的对象都在这里；空间大、速度相对慢；被所有线程共享；**由垃圾回收器（GC）管理**。

**基本类型与引用类型的存储差异（本课时的核心）**：

```java
public void test() {
    int a = 10;                    // 基本类型：值 10 直接存在栈上
    String s = "hello";            // 引用类型：栈上存地址，"hello" 对象在常量池/堆
    int[] arr = {1, 2, 3};         // 栈上存地址，数组对象在堆
    User u = new User();           // 栈上存地址，User 对象在堆
}
```

**内存图示**：

```
        栈（Stack）                        堆（Heap）
    ┌──────────────────┐            ┌────────────────────┐
    │  a   │   10      │            │                    │
    │  s   │ 0x1A2B ───┼───────────▶│ "hello"            │
    │ arr  │ 0x3C4D ───┼───────────▶│ [1, 2, 3]          │
    │  u   │ 0x5E6F ───┼───────────▶│ User{name=null}    │
    └──────────────────┘            └────────────────────┘
      存值 / 存地址                      存实际对象
```

**「引用」到底是什么**。引用变量存的不是对象本身，而是**对象在堆中的地址**（可以理解为门牌号）。所以：

```java
int[] arr1 = {1, 2, 3};
int[] arr2 = arr1;         // 复制的是地址！两个变量指向同一个数组
arr1[0] = 100;
System.out.println(arr2[0]);   // 100  ← 跟着变了

int a = 10;
int b = a;                 // 复制的是值
a = 20;
System.out.println(b);     // 10   ← 不变
```

这个差异是理解 Java 参数传递、对象比较、集合行为的基础。

**方法参数传递：Java 只有值传递（面试必考）**：

```java
public static void change(int x) { x = 100; }
public static void change(int[] arr) { arr[0] = 100; }
public static void reassign(int[] arr) { arr = new int[]{9,9,9}; }

int a = 10;
change(a);
System.out.println(a);          // 10   基本类型：传的是值的副本

int[] arr = {1,2,3};
change(arr);
System.out.println(arr[0]);     // 100  引用类型：传的是地址副本，指向同一对象

reassign(arr);
System.out.println(arr[0]);     // 100  ← 仍是 100！方法内改的是地址副本的指向
```

**结论**：Java 中**永远是值传递**。对引用类型来说，传递的是「地址值」的副本 —— 所以能通过这个地址修改对象内容，但**无法改变原变量指向哪个对象**。

**局部变量为什么必须初始化**：局部变量在栈上分配，栈帧频繁创建销毁，JVM 不做清零操作（有性能开销）。而堆上的对象在分配时会被 JVM 统一清零，所以成员变量有默认值。

**常见内存错误**：

```java
// StackOverflowError：栈溢出，通常是无限递归
public void recurse() { recurse(); }

// OutOfMemoryError: Java heap space：堆溢出，对象太多或内存泄漏
List<byte[]> list = new ArrayList<>();
while (true) { list.add(new byte[1024*1024]); }
```

## 6.5 引用的比较方式

**本课时对应知识点**：`==` 和 `equals()` 的比较。

**核心规则（面试必答）**：

| | `==` | `equals()` |
|---|---|---|
| 本质 | **运算符** | **方法** |
| 基本类型 | 比较**值** | 不适用（基本类型没有方法） |
| 引用类型 | 比较**地址**（是否同一对象） | 默认比较地址；**重写后比较内容** |

```java
int a = 10, b = 10;
System.out.println(a == b);          // true  基本类型比值

String s1 = new String("hello");
String s2 = new String("hello");
System.out.println(s1 == s2);        // false 两个不同对象，地址不同
System.out.println(s1.equals(s2));   // true  String 重写了 equals，比内容
```

**Object 类的 equals 默认实现**：

```java
public boolean equals(Object obj) {
    return (this == obj);       // 默认就是 ==，比较地址
}
```

所以**自定义类如果不重写 equals，`equals()` 和 `==` 效果完全一样**：

```java
class User {
    String name;
    User(String name) { this.name = name; }
}

User u1 = new User("张三");
User u2 = new User("张三");
System.out.println(u1.equals(u2));   // false！没重写 equals，比的是地址
```

**重写 equals 的标准写法**：

```java
@Override
public boolean equals(Object o) {
    if (this == o) return true;                          // ① 地址相同，必相等
    if (o == null || getClass() != o.getClass()) return false;  // ② 类型检查
    User user = (User) o;                                // ③ 向下转型
    return Objects.equals(name, user.name);              // ④ 逐字段比较
}

@Override
public int hashCode() {
    return Objects.hash(name);
}
```

**为什么重写 equals 必须同时重写 hashCode（重要）**。Java 规定：**两个对象 equals 相等，它们的 hashCode 必须相等**。HashMap、HashSet 先用 hashCode 定位桶，再用 equals 确认。只重写 equals 不重写 hashCode 会导致：

```java
Set<User> set = new HashSet<>();
set.add(new User("张三"));
set.add(new User("张三"));
System.out.println(set.size());   // 2！本以为会去重，结果没有
```

因为两个对象 hashCode 不同，被分到了不同的桶，`equals` 根本没机会被调用。

**IDEA 快捷生成**：`Alt + Insert` → `equals() and hashCode()`，自动生成规范实现。用 Lombok 的 `@Data` 或 `@EqualsAndHashCode` 也会自动生成（见 JB1-3 龙目岛工具类）。

**字符串比较的实践建议**：

```java
// ① 永远用 equals 比较字符串内容，不要用 ==
if (str.equals("abc")) { ... }

// ② 常量放前面，防止空指针（Yoda 表达式）
if ("abc".equals(str)) { ... }        // str 为 null 也不会报错，返回 false
if (str.equals("abc")) { ... }        // str 为 null 时抛 NullPointerException

// ③ 忽略大小写
if (str.equalsIgnoreCase("ABC")) { ... }

// ④ JDK 7+ 的空安全写法
if (Objects.equals(str, "abc")) { ... }
```

**包装类比较的经典陷阱**（与下一课时相关）：

```java
Integer a = 100, b = 100;
System.out.println(a == b);         // true  ❗

Integer c = 200, d = 200;
System.out.println(c == d);         // false ❗❗
System.out.println(c.equals(d));    // true
```

**原因**：`Integer` 有**缓存池**，缓存了 **−128 ~ 127** 范围的对象。100 在缓存范围内，`a` 和 `b` 指向缓存中的同一个对象；200 超出范围，各自新建对象，地址不同。

**结论：包装类必须用 `equals()` 比较，绝不能用 `==`**。阿里巴巴开发手册对此有明确规定。

## 6.6 装箱和拆箱过程

**本课时对应知识点**：包装类、手动拆装箱、自动拆装箱、基本类型和引用类型的区别。

**为什么需要包装类**。Java 的基本类型不是对象，无法参与面向对象的体系 —— 不能放进集合（`List<int>` 是非法的）、不能调用方法、不能表示"没有值"（null）。**包装类就是把基本类型包装成对象**。

**8 种基本类型对应的包装类**：

| 基本类型 | 包装类 | 注意 |
|---|---|---|
| `byte` | `Byte` | |
| `short` | `Short` | |
| `int` | **`Integer`** | ⚠️ 不是 Int |
| `long` | `Long` | |
| `float` | `Float` | |
| `double` | `Double` | |
| `char` | **`Character`** | ⚠️ 不是 Char |
| `boolean` | `Boolean` | |

**记忆点**：只有 `int → Integer` 和 `char → Character` 不是简单地首字母大写。

**手动装箱与拆箱（JDK 5 之前的写法）**：

```java
// 手动装箱：基本类型 → 包装类
Integer i1 = Integer.valueOf(10);
Integer i2 = new Integer(10);       // ⚠️ JDK 9 起已标记为过时，不要用

// 手动拆箱：包装类 → 基本类型
int n = i1.intValue();
```

**自动装箱与拆箱（JDK 5+，语法糖）**：

```java
Integer i = 10;        // 自动装箱，编译后是 Integer.valueOf(10)
int n = i;             // 自动拆箱，编译后是 i.intValue()

List<Integer> list = new ArrayList<>();
list.add(10);          // 自动装箱
int first = list.get(0);   // 自动拆箱
```

**用 jclasslib 插件查看字节码**（见 JB1-1 第 3 单元），能清楚看到编译器插入的 `valueOf` 和 `intValue` 调用 —— 这是理解「语法糖」最直观的方式。

**Integer 缓存机制（面试高频）**：

```java
public static Integer valueOf(int i) {
    if (i >= IntegerCache.low && i <= IntegerCache.high)
        return IntegerCache.cache[i + (-IntegerCache.low)];   // 命中缓存
    return new Integer(i);                                     // 新建对象
}
```

**默认缓存范围是 −128 ~ 127**。设计原因是这个区间的小整数使用频率极高，缓存能显著减少对象创建。上限可通过 JVM 参数 `-XX:AutoBoxCacheMax=N` 调整。

**各包装类的缓存情况**：`Byte`、`Short`、`Integer`、`Long` 缓存 −128~127；`Character` 缓存 0~127；`Boolean` 缓存 `TRUE` 和 `FALSE`；**`Float` 和 `Double` 没有缓存**（浮点数取值连续，无法缓存）。

**自动拆箱的空指针陷阱（实际项目高频 bug）**：

```java
Integer count = null;
int n = count;                    // ❌ NullPointerException！拆箱时调用 null.intValue()

Map<String, Integer> map = new HashMap<>();
int value = map.get("不存在的key");  // ❌ NPE，get 返回 null 再拆箱

Boolean flag = null;
if (flag) { ... }                 // ❌ NPE
```

**这类空指针非常隐蔽**，因为代码表面上看不到任何方法调用。从数据库、接口、Map 取回的包装类型都可能是 null，使用前必须判空。

**混合运算时的自动拆箱**：

```java
Integer a = 100;
int b = 100;
System.out.println(a == b);       // true  ← a 自动拆箱后比较值

Integer c = 200;
Integer d = 200;
System.out.println(c == d);       // false ← 两个包装类比较，比的是地址

Long e = 200L;
System.out.println(e.equals(200));       // false ❗ 类型不同（Long vs Integer）
System.out.println(e.equals(200L));      // true
```

**规则**：包装类与基本类型比较（`==`）时，包装类会拆箱，比较的是**值**；包装类之间比较（`==`）时，比较的是**地址**。`equals()` 则会同时检查**类型和值**。

**包装类的实用方法**：

```java
Integer.parseInt("123");           // String → int
Integer.valueOf("123");            // String → Integer
Integer.toString(123);             // int → String
String.valueOf(123);               // 任意 → String
Integer.MAX_VALUE;                 // 最大值常量
Integer.toBinaryString(10);        // "1010"
Integer.compare(a, b);             // 比较大小
Double.parseDouble("3.14");
Boolean.parseBoolean("true");
```

**`parseInt` 与 `valueOf` 的区别**：`parseInt` 返回基本类型 `int`；`valueOf` 返回包装类 `Integer`（且会走缓存）。

**基本类型 vs 引用类型对比总结**：

| | 基本类型 | 引用类型（包装类） |
|---|---|---|
| 存储 | 栈上直接存值 | 栈存地址，对象在堆 |
| 默认值 | 0 / false | **null** |
| 能否为 null | ❌ | ✅ |
| 能否进集合 | ❌ | ✅ |
| 能否调方法 | ❌ | ✅ |
| 比较方式 | `==` | `equals()` |
| 性能 | 高 | 略低（有对象开销） |

**选型建议**：局部变量、循环计数器用**基本类型**（性能好，不会 NPE）；**实体类字段用包装类**（能表示「未设置」这个状态 —— 比如 `int price = 0` 无法区分「价格是 0 元」和「还没填价格」，而 `Integer price = null` 可以）。阿里巴巴开发手册也明确规定：**POJO 类的属性必须使用包装数据类型，RPC 方法的返回值和参数必须使用包装数据类型，局部变量推荐使用基本数据类型**。
