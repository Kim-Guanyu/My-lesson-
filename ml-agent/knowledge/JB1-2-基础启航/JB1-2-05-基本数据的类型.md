## 5.1 基本类型之整数

**本课时对应知识点**：`byte`、`short`、`int`、`long`，存值范围，javac 范围检查过程。

**四种整数类型**：

| 类型 | 占用 | 位数 | 取值范围 | 默认值 |
|---|---|---|---|---|
| `byte` | 1 字节 | 8 位 | −128 ~ 127 | 0 |
| `short` | 2 字节 | 16 位 | −32768 ~ 32767 | 0 |
| **`int`** | 4 字节 | 32 位 | −2147483648 ~ 2147483647（约 ±21 亿） | 0 |
| `long` | 8 字节 | 64 位 | 约 ±9.22×10¹⁸ | 0L |

**范围的计算公式**：n 位有符号整数的范围是 **−2ⁿ⁻¹ ~ 2ⁿ⁻¹−1**。负数比正数多一个，原因见 3.3 课时的补码原理（`1000 0000` 被用来表示 −128 而不是 −0）。

**用常量查看范围**：

```java
System.out.println(Byte.MIN_VALUE + " ~ " + Byte.MAX_VALUE);       // -128 ~ 127
System.out.println(Short.MIN_VALUE + " ~ " + Short.MAX_VALUE);     // -32768 ~ 32767
System.out.println(Integer.MIN_VALUE + " ~ " + Integer.MAX_VALUE); // -2147483648 ~ 2147483647
System.out.println(Long.MIN_VALUE + " ~ " + Long.MAX_VALUE);
```

**long 类型必须加 L 后缀**：

```java
long a = 100;              // ✅ 100 是 int 字面量，小转大自动提升
long b = 10000000000;      // ❌ 编译错误：整数太大，超出了 int 范围
long c = 10000000000L;     // ✅ 加 L 后缀，直接就是 long 字面量
```

**关键理解**：字面量 `10000000000` 在被赋值之前，编译器先把它当作 **int** 处理，而它超出了 int 范围，所以在「赋值给 long」这一步之前就已经报错了。加 `L` 是告诉编译器「这是一个 long 字面量」。推荐用**大写 L**，小写 `l` 与数字 `1` 极易混淆。

**javac 的范围检查过程（本课时的核心考点）**。观察这组代码：

```java
byte b1 = 100;      // ✅ 编译通过
byte b2 = 200;      // ❌ 编译错误：不兼容的类型，从 int 转换到 byte 可能会有损失

int i = 100;
byte b3 = i;        // ❌ 编译错误：即使 i 的值是 100，也不行！
```

**为什么 `byte b1 = 100;` 可以，而 `byte b3 = i;` 不行**？

javac 有一个**常量折叠 + 隐式窄化**的特殊规则：

1. 当右侧是**编译期常量**（字面量、或 final 修饰且值确定的变量）时，编译器会在编译期**检查这个常量值是否落在左侧类型的范围内**。在范围内就自动加隐式强转，编译通过。
2. 当右侧是**变量**时，编译器无法在编译期知道它的运行时值（`i` 可能在别处被改成 1000），出于安全考虑**一律拒绝**，必须由程序员显式强转 `byte b3 = (byte) i;` 来表示「我知道可能损失精度，我承担后果」。

这个规则适用于 `byte`、`short`、`char` 三种类型的赋值。验证：

```java
final int i = 100;
byte b = i;         // ✅ 编译通过！因为 final 使 i 成为编译期常量
```

**整数运算的自动提升（重要）**。**所有小于 int 的类型（byte、short、char）参与运算时，都会先被提升为 int**：

```java
byte a = 10, b = 20;
byte c = a + b;         // ❌ 编译错误：a+b 的结果是 int
int  d = a + b;         // ✅
byte e = (byte)(a + b); // ✅ 显式强转
```

原因是 CPU 的运算单元以 32 位为基本宽度，用 int 运算效率最高，语言设计上也避免了小类型频繁溢出。

**整数除法的截断**：

```java
System.out.println(5 / 2);        // 2   ← 不是 2.5！整数除法直接舍弃小数部分
System.out.println(5.0 / 2);      // 2.5 ← 有一方是浮点就按浮点算
System.out.println(-5 / 2);       // -2  ← 向零取整，不是向下取整
System.out.println(5 % 2);        // 1   ← 取余
System.out.println(-5 % 2);       // -1  ← 余数符号跟随被除数
```

**除零行为**：

```java
System.out.println(5 / 0);        // ❌ 运行时抛 ArithmeticException: / by zero
System.out.println(5.0 / 0);      // Infinity（浮点数除零不报错！）
```

**选型建议**：日常整数一律用 `int`；表示时间戳、金额分、大 ID 用 `long`；`byte` 主要用于**字节流和二进制数据处理**（如 `byte[]` 读文件）；`short` 几乎用不到。**不要为了省内存而用 byte/short**，现代内存不缺这几个字节，反而会因为频繁的类型转换引入 bug。

## 5.2 基本类型之浮点

**本课时对应知识点**：`float`、`double`，浮点数默认类型，浮点数天生不精确。

**两种浮点类型**：

| 类型 | 占用 | 有效位数 | 默认值 |
|---|---|---|---|
| `float` | 4 字节 | 约 6–7 位十进制有效数字 | 0.0f |
| **`double`** | 8 字节 | 约 15–16 位十进制有效数字 | 0.0d |

**浮点字面量默认是 double**：

```java
double d = 3.14;      // ✅
float f = 3.14;       // ❌ 编译错误：不兼容的类型，double 无法转换为 float
float f = 3.14F;      // ✅ 加 F 后缀
float f = (float)3.14;// ✅ 强转也可以
double d2 = 3.14D;    // D 后缀可以省略
```

**浮点数天生不精确（本课时最重要的知识点）**：

```java
System.out.println(0.1 + 0.2);            // 0.30000000000000004  ❗
System.out.println(0.1 + 0.2 == 0.3);     // false                ❗
System.out.println(1.0 - 0.9);            // 0.09999999999999998
System.out.println(4.35 * 100);           // 434.99999999999994
```

**为什么不精确**。浮点数遵循 **IEEE 754** 标准，用「符号位 + 指数位 + 尾数位」的二进制科学计数法存储。问题在于：**很多十进制小数无法用有限位二进制精确表示**。

以 0.1 为例，转成二进制是无限循环小数：

```
0.1(十进制) = 0.0001100110011001100...(二进制，1100 无限循环)
```

就像十进制无法精确表示 1/3（0.333... 永远除不尽）一样，二进制无法精确表示 0.1。存储时必须在某一位截断，误差就此产生，多次运算后误差还会累积放大。

**三条实用规则**：

**① 浮点数绝对不能用 `==` 比较**。要判断是否相等，应比较差值是否在允许误差内：

```java
double a = 0.1 + 0.2;
double b = 0.3;
System.out.println(a == b);                        // ❌ false
System.out.println(Math.abs(a - b) < 1e-9);        // ✅ true
```

**② 金额计算绝对不能用 float / double，必须用 `BigDecimal`**：

```java
import java.math.BigDecimal;

// ❌ 错误示范
double price = 0.1, count = 3;
System.out.println(price * count);      // 0.30000000000000004 —— 财务对不上账

// ✅ 正确做法
BigDecimal p = new BigDecimal("0.1");   // 注意：必须用 String 构造器！
BigDecimal c = new BigDecimal("3");
System.out.println(p.multiply(c));      // 0.3
```

> **BigDecimal 的关键坑**：一定要用 **String 构造器**。`new BigDecimal(0.1)` 传的是 double，误差在传参时就已经产生了，结果是 `0.1000000000000000055511151231257827...`。

BigDecimal 常用方法：`add()` 加、`subtract()` 减、`multiply()` 乘、`divide()` 除（除法必须指定精度和舍入模式，否则除不尽时抛 `ArithmeticException`）、`compareTo()` 比较大小（**不要用 `equals()`**，因为 `equals` 会比较标度，`2.0` 和 `2.00` 会被判为不相等）。

本平台（知堂课堂）的课程价格字段用的就是 `BigDecimal`，数据库对应 `decimal(8,2)`。

**③ 涉及金额时，另一个常见方案是「用 long 存分」**。把 12.34 元存成 1234 分，全程整数运算，展示时再除以 100。电商和支付系统常用这种做法。

**特殊值**：

```java
System.out.println(1.0 / 0);            // Infinity      正无穷
System.out.println(-1.0 / 0);           // -Infinity     负无穷
System.out.println(0.0 / 0);            // NaN           非数字 Not a Number
System.out.println(Double.NaN == Double.NaN);      // false！NaN 与任何值都不相等
System.out.println(Double.isNaN(0.0 / 0));         // true  ← 判断 NaN 的正确方式
```

注意**浮点数除零不抛异常**，而整数除零抛 `ArithmeticException`。

**选型建议**：科学计算、一般小数用 `double`（现代 CPU 对 double 的支持很好，不比 float 慢）；`float` 只在需要大量存储且精度要求低时用（如图形处理）；**金额、精确计算一律 BigDecimal**。

## 5.3 基本类型之字符

**本课时对应知识点**：`char`，存值范围，字符存储内容，javac 范围检查过程。

**char 的本质**：

| 类型 | 占用 | 范围 | 默认值 |
|---|---|---|---|
| `char` | 2 字节（16 位） | **0 ~ 65535**（无符号！） | ` ` |

**char 是唯一的无符号基本类型**，因为字符编号没有负数。它存储的是 **Unicode 码点**（UTF-16 编码单元），因此**能直接存中文**：

```java
char c1 = 'A';           // 字符字面量，单引号
char c2 = 65;            // ✅ 用码值赋值，结果也是 'A'
char c3 = '中';          // ✅ 2 字节能装下常用汉字
char c4 = '\u0041';  // ✅ Unicode 转义写法，等价于 'A'
char c5 = "A";           // ❌ 编译错误：双引号是 String，不是 char
char c6 = 'AB';          // ❌ 编译错误：char 只能存一个字符
```

**char 与 int 的互转**：

```java
char c = 'A';
int i = c;                        // ✅ 自动提升：65
System.out.println(c + 1);        // 66  ← char 参与运算自动提升为 int
System.out.println((char)(c + 1));// B   ← 强转回 char
System.out.println((int)'中');     // 20013
System.out.println((char)20013);  // 中
```

**常用字符的码值（值得记住）**：

| 字符 | 码值 |
|---|---|
| `'0'` ~ `'9'` | 48 ~ 57 |
| `'A'` ~ `'Z'` | 65 ~ 90 |
| `'a'` ~ `'z'` | 97 ~ 122 |
| `' '`（空格） | 32 |

**由此推出两个常用技巧**：

```java
// 数字字符转数字：减去 '0'
char digit = '7';
int num = digit - '0';            // 7（因为 '7' 是 55，'0' 是 48）

// 大小写转换：相差 32
char upper = 'A';
char lower = (char)(upper + 32);  // 'a'
// 实际开发直接用 Character.toLowerCase(upper) 更清晰
```

**javac 对 char 的范围检查**（与 5.1 的整数规则完全一致）：

```java
char c1 = 65;         // ✅ 编译期常量 65 在 0~65535 内，自动隐式转换
char c2 = 70000;      // ❌ 编译错误：超出 char 范围
char c3 = -1;         // ❌ 编译错误：char 是无符号的，不能为负

int i = 65;
char c4 = i;          // ❌ 编译错误：变量无法在编译期确定值
char c5 = (char) i;   // ✅ 显式强转

final int j = 65;
char c6 = j;          // ✅ final 使 j 成为编译期常量
```

**char 与 String 的区别（初学者高频混淆点）**：

| | `char` | `String` |
|---|---|---|
| 类型 | **基本类型** | **引用类型**（类） |
| 引号 | 单引号 `'A'` | 双引号 `"A"` |
| 长度 | 固定一个字符 | 0 到任意多个字符 |
| 存储位置 | 栈（局部变量） | 堆 / 字符串常量池 |
| `+` 运算 | 按码值做算术加法 | 字符串拼接 |

```java
System.out.println('a' + 'b');      // 195  （97 + 98，算术加法）
System.out.println("a" + "b");      // ab   （字符串拼接）
System.out.println('a' + "b");      // ab   （有一方是 String，转为拼接）
```

**Character 工具类的常用方法**：

```java
Character.isDigit('5');         // true   是否数字
Character.isLetter('A');        // true   是否字母
Character.isUpperCase('A');     // true   是否大写
Character.isLowerCase('a');     // true   是否小写
Character.isLetterOrDigit('_'); // false
Character.isWhitespace(' ');    // true   是否空白
Character.toUpperCase('a');     // 'A'
Character.toLowerCase('A');     // 'a'
```

**关于 emoji 和生僻字**。Unicode 现已超过 65535 个码点，超出部分（增补平面）需要**两个 char**（代理对 Surrogate Pair）来表示：

```java
String emoji = "😀";
System.out.println(emoji.length());          // 2  ← 不是 1！
System.out.println(emoji.codePointCount(0, emoji.length()));  // 1  ← 真实字符数
```

这解释了为什么用 `length()` 统计含 emoji 的字符串长度会偏大，也是数据库里存 emoji 需要用 `utf8mb4` 而不是 `utf8` 的原因（MySQL 的 `utf8` 每字符最多 3 字节，装不下 4 字节的 emoji）。

## 5.4 基本类型之布尔

**本课时对应知识点**：`boolean`，存值范围，二进制位中的真实存储位置。

**boolean 只有两个值**：

```java
boolean flag1 = true;
boolean flag2 = false;
boolean flag3 = 1;        // ❌ 编译错误！Java 中 1 不等于 true
boolean flag4 = (5 > 3);  // ✅ 关系运算的结果就是 boolean
```

**与 C/C++ 的重要区别**：C 语言中 `0` 是假、非 `0` 是真，可以写 `if (5)`。**Java 严格区分**，`if` 的条件必须是 boolean 表达式，不能是数字。这消除了 C 里经典的 `if (a = 1)`（误把 `==` 写成 `=`）的隐蔽 bug —— 在 Java 中这会直接编译报错（除非 a 本身就是 boolean）。

**boolean 占几个字节？（经典面试题）**

**Java 规范没有明确定义 boolean 的存储大小**，这是一个由 JVM 实现决定的细节。HotSpot 虚拟机的实际做法是：

- **单个 boolean 变量**：编译后用 **int 表示**（栈上占 4 字节），因为 JVM 没有专门的 boolean 指令，字节码里 `true` 是 `1`、`false` 是 `0`
- **boolean 数组（`boolean[]`）**：按 **byte 数组**处理，每个元素占 **1 字节**（有专门的 `baload`/`bastore` 指令）

所以标准答案是：**规范未定义；HotSpot 中单个 boolean 按 int（4 字节）处理，数组元素按 byte（1 字节）处理**。

**理论上只需 1 位（bit）就够**，但 CPU 访问内存的最小单位是字节，按位存储反而需要额外的位运算开销，得不偿失。真正需要极致压缩时，用 `BitSet` 类（见 JB1-4 线性结构工具），它内部用 long 数组按位存储。

**boolean 的默认值是 `false`**（成员变量），局部变量仍然必须手动初始化。

**boolean 的典型用法**：

```java
// 1. 条件判断
if (isValid) { ... }

// 2. 方法返回值（判断类方法）
public boolean isEmpty() { return size == 0; }

// 3. 标志位
boolean found = false;
for (int i = 0; i < arr.length; i++) {
    if (arr[i] == target) {
        found = true;
        break;
    }
}
```

**boolean 不参与类型转换**。它与其他 7 种基本类型之间**没有任何自动或强制转换关系**：

```java
int i = (int) true;         // ❌ 编译错误
boolean b = (boolean) 1;    // ❌ 编译错误
```

需要转换时只能手动写逻辑：`boolean b = (i != 0);`

**代码风格建议**：

```java
if (flag == true) { ... }     // ❌ 冗余
if (flag) { ... }             // ✅

if (flag == false) { ... }    // ❌
if (!flag) { ... }            // ✅

return a > b ? true : false;  // ❌ 多此一举
return a > b;                 // ✅
```

**包装类 Boolean 的注意事项**：

```java
Boolean b = null;
if (b) { ... }              // ❌ 运行时抛 NullPointerException（自动拆箱时）
if (Boolean.TRUE.equals(b)) { ... }   // ✅ 安全写法
```

从数据库或接口取回的 `Boolean` 可能是 `null`，直接放进 `if` 会在自动拆箱时空指针。这是实际项目中很常见的坑。

## 5.5 基本类型的转换

**本课时对应知识点**：强转格式、强转原则、char 类型的转换过程、整数和浮点数的转换效果。

**8 种基本类型总览**（`boolean` 不参与转换）：

```
byte(1) → short(2) → int(4) → long(8) → float(4) → double(8)
            ↑
         char(2)
```

**自动类型转换（隐式转换 / 小转大）**。沿着箭头方向，编译器自动完成，无需任何语法：

```java
byte b = 10;
int i = b;          // ✅ byte → int
long l = i;         // ✅ int → long
float f = l;        // ✅ long → float
double d = f;       // ✅ float → double

char c = 'A';
int ci = c;         // ✅ char → int（65）
```

**注意 long(8字节) → float(4字节) 也是自动转换**，看起来「大转小」，但因为**浮点数的表示范围远大于整数**（float 最大约 3.4×10³⁸，long 最大约 9.2×10¹⁸），所以不会溢出 —— 只是可能损失精度：

```java
long big = 123456789123456789L;
float f = big;
System.out.println((long) f);   // 123456790519087104  ← 精度丢失了
```

**强制类型转换（显式转换 / 大转小）**。逆着箭头方向，**必须手动写强转，且可能损失数据**：

```java
目标类型 变量名 = (目标类型) 原值;
```

```java
int i = 300;
byte b = (byte) i;
System.out.println(b);      // 44  ❗ 数据被截断了
```

**为什么 300 强转 byte 得到 44**（用 3.3 课时的补码知识解释）：

```
300 的 int 补码（32位）：00000000 00000000 00000001 00101100
强转 byte 只保留低 8 位：                            00101100
00101100 = 44（最高位是 0，是正数）
```

**强转就是「简单粗暴地砍掉高位」**。再看一个会变成负数的例子：

```java
int i = 200;
byte b = (byte) i;
System.out.println(b);      // -56
// 200 的低8位是 11001000，最高位为 1 → 是负数
// 补码 11001000 → 反码 11000111 → 原码 10111000 = -56
```

**强转原则总结**：

1. **能不强转就不强转** —— 强转意味着你在承诺「我知道不会丢数据」
2. 强转前应检查范围，或用包装类的安全方法（如 `Math.toIntExact(long)`，超范围会抛异常而不是静默截断）
3. 强转只影响**本次取值**，不改变原变量：`(byte) i` 之后 `i` 仍然是 300

**浮点转整数：直接砍掉小数部分（向零取整），不是四舍五入**：

```java
System.out.println((int) 3.9);      // 3   ← 不是 4！
System.out.println((int) 3.1);      // 3
System.out.println((int) -3.9);     // -3  ← 向零取整，不是 -4
System.out.println(Math.round(3.9));  // 4  ← 需要四舍五入用 Math.round
System.out.println(Math.round(-3.5)); // -3 ← round 是「加0.5后向下取整」
```

**char 的转换过程（本课时的重点）**：

```java
// char → int：自动，取码值
char c = 'A';
int i = c;                  // 65

// int → char：需强转（除非是编译期常量且在范围内）
int num = 66;
char c2 = (char) num;       // 'B'

// char → byte / short：需强转，因为范围不兼容
char c3 = '中';              // 码值 20013
byte b = (byte) c3;         // ❗ 严重截断，得到无意义的值

// byte → char：也需要强转！
byte b2 = 65;
char c4 = (char) b2;        // 'A'
```

**为什么 byte → char 需要强转**（考点）：byte 范围是 −128~127（**有符号**），char 范围是 0~65535（**无符号**）。byte 的负数区间在 char 中不存在，两者范围**互不包含**，所以任何方向都需要显式强转。同理 `short`（−32768~32767）与 `char` 之间也必须强转。

**混合运算的自动提升规则（重要）**。表达式中有多种类型时，**统一提升为其中最大的类型**：

```java
byte + short  → int      （所有小于 int 的都先升 int）
int + long    → long
long + float  → float
float + double→ double
char + int    → int
```

```java
byte a = 10;
short b = 20;
// byte c = a + b;      ❌ 结果是 int
int c = a + b;          // ✅

int x = 10;
double y = 3.5;
// int z = x + y;       ❌ 结果是 double
double z = x + y;       // ✅ 13.5
```

## 5.6 跨类型计算原则

**本课时对应知识点**：测试不同类型之间计算，结果是否一定返回最大类型。

**基本规则：结果类型 = 参与运算的类型中「等级最高」的那个**，且**最低不低于 int**。

类型等级从低到高：`byte` < `short` = `char` < `int` < `long` < `float` < `double`

**验证代码**：

```java
byte  b = 1;
short s = 2;
char  c = 3;
int   i = 4;
long  l = 5L;
float f = 6.0F;
double d = 7.0;

// 全部小于 int 的类型，结果一律是 int
int r1 = b + s;         // int
int r2 = b + c;         // int
int r3 = b + b;         // int  ← 即使两个都是 byte！
int r4 = c + c;         // int  ← 两个 char 相加也是 int

long r5 = i + l;        // long
float r6 = l + f;       // float
double r7 = f + d;      // double
```

**用 `getClass()` 实测（借助自动装箱）**：

```java
byte a = 1, b2 = 2;
System.out.println(((Object)(a + b2)).getClass().getName());
// java.lang.Integer   ← 证明 byte+byte 的结果确实是 int
```

**「是否一定返回最大类型」的答案是：是，但有下限**。核心是那条下限规则 —— **byte、short、char 参与任何算术运算，都先无条件提升为 int**。这就是为什么 `byte + byte` 的结果是 int 而不是 byte。

**这条规则的两个实践后果**：

```java
// 后果一：小类型的运算结果需要强转才能赋回小类型
byte a = 10, b = 20;
byte c = (byte)(a + b);      // 必须强转

// 后果二：复合赋值运算符自带隐式强转，所以不用手写
byte d = 10;
d += 20;                     // ✅ 等价于 d = (byte)(d + 20)
d++;                         // ✅ 同理，自增自减也自带强转
```

**几个易错的跨类型场景**：

```java
// ① 整数除法优先于类型提升
System.out.println(1 / 2);              // 0    两个 int，整数除法
System.out.println(1 / 2 * 3.0);        // 0.0  先算 1/2=0，再乘 3.0
System.out.println(1 / 2.0 * 3);        // 1.5  先算 1/2.0=0.5
System.out.println(3.0 * 1 / 2);        // 1.5  从左往右，3.0*1=3.0，再除 2

// ② char 参与运算变成 int
char c = 'a';
System.out.println(c + 1);              // 98
System.out.println("" + c + 1);         // a1
System.out.println((char)(c + 1));      // b

// ③ long 与 int 混合，小心中间结果溢出
int a = 1000000;
long r = a * a;                         // ❗ -727379968（错误！）
long r2 = (long) a * a;                 // ✅ 1000000000000
```

第 ③ 个例子是**实际项目中的经典 bug**：`a * a` 两边都是 int，运算在 int 范围内进行并溢出，溢出后的错误值才被提升为 long。**必须在运算前就强转一方为 long**。计算时间戳毫秒数、大数据量统计时经常踩这个坑。

**三目运算符的类型提升（冷门但常考）**：

```java
Object o = true ? new Integer(1) : new Double(2.0);
System.out.println(o);          // 1.0  ❗ 不是 1！
```

三目运算符的两个分支会做**类型提升到共同类型**，Integer 和 Double 提升为 double，所以结果是 `1.0`。这是 Java 中很隐蔽的一个陷阱。

**布尔类型完全独立**：`boolean` 不参与任何类型提升和转换，它与其他 7 种类型之间没有任何转换通道。

## 5.7 计算结果的溢出

**本课时对应知识点**：为何最大值加 1 变最小值，最小值减 1 变最大值。

**溢出现象演示**：

```java
System.out.println(Integer.MAX_VALUE);        // 2147483647
System.out.println(Integer.MAX_VALUE + 1);    // -2147483648  ❗ 变成了最小值

System.out.println(Integer.MIN_VALUE);        // -2147483648
System.out.println(Integer.MIN_VALUE - 1);    // 2147483647   ❗ 变成了最大值

byte b = 127;
b++;
System.out.println(b);                        // -128
```

**原理（补码的必然结果，见 3.3 课时）**：

```
最大值 2147483647 的补码：0111 1111 1111 1111 1111 1111 1111 1111
                    + 1 : 1000 0000 0000 0000 0000 0000 0000 0000
                        = -2147483648（符号位被进位改成了 1）
```

**关键理解**：加法运算不管符号位，最高位的 1 就意味着「负数」。所以最大正数加 1，符号位被进位「污染」，直接翻转成最小负数。

反过来：

```
最小值 -2147483648 的补码：1000 0000 0000 0000 0000 0000 0000 0000
                    - 1 : 0111 1111 1111 1111 1111 1111 1111 1111
                        = 2147483647
```

**整数范围是一个环（最好的记忆模型）**：

```
        ... -2  -1   0   1   2 ...
        ↑                        ↓
   MIN_VALUE ←───────────── MAX_VALUE
        （首尾相接，像时钟一样绕圈）
```

时钟走到 12 点再走一格回到 1 点，整数溢出是同一个道理。这种运算在数学上叫**模运算（modular arithmetic）**。

**Java 对溢出的态度：静默发生，不报错**。这是最危险的地方 —— 程序不会崩溃，只是给你一个错误的结果，可能在很久之后才被发现。

**实际项目中的溢出案例**：

```java
// ① 大数相乘
int a = 100000, b = 100000;
System.out.println(a * b);              // 1410065408  ❗ 正确答案是 10000000000
System.out.println((long) a * b);       // 10000000000 ✅

// ② 时间计算（毫秒数很容易超 int）
int days = 30;
int ms = days * 24 * 60 * 60 * 1000;    // ❗ 溢出：2592000000 > 21亿
long ms2 = days * 24L * 60 * 60 * 1000; // ✅ 加 L 让运算在 long 中进行

// ③ 二分查找的经典 bug（JDK 早期版本真实存在过）
int mid = (low + high) / 2;             // ❗ low+high 可能溢出
int mid2 = low + (high - low) / 2;      // ✅ 正确写法
```

**如何防范溢出**：

**① 选对类型**。可能超过 21 亿的场景一律用 `long`。金额用 `BigDecimal`，超大整数用 `BigInteger`（理论上无上限）。

**② 用 Math 的精确方法（JDK 8+）**。溢出时**抛异常**而不是静默出错：

```java
Math.addExact(Integer.MAX_VALUE, 1);        // 抛 ArithmeticException: integer overflow
Math.multiplyExact(100000, 100000);         // 抛异常
Math.subtractExact(a, b);
Math.toIntExact(longValue);                 // long 转 int，超范围抛异常
```

**在金融、计数等不容出错的场景，应优先用这些方法** —— 让程序响亮地失败，好过悄悄给出错误数据。

**③ 运算前先强转**。`(long) a * b` 而不是 `(long)(a * b)` —— 后者是先在 int 中算完（已经溢出）再转 long，为时已晚。

**④ 边界测试**。写单元测试时专门覆盖 `MAX_VALUE`、`MIN_VALUE`、`0`、`±1` 这些边界值。

**浮点数没有溢出，但有 Infinity**：

```java
System.out.println(Double.MAX_VALUE * 2);   // Infinity（不会变成负数）
System.out.println(1.0 / 0);                // Infinity
System.out.println(0.0 / 0);                // NaN
```

浮点数超出范围会变成 `Infinity` 而不是回绕，这与整数的行为完全不同。
