## 4.1 变量的声明方式

**本课时对应知识点**：变量的声明方式、强类型、同行声明方式。

**变量是什么**。变量是**内存中一块可以重复赋值的存储空间**，由三要素构成：**数据类型**（决定占多少内存、能存什么）、**变量名**（访问它的标识）、**值**（实际存储的内容）。

**基本声明格式**：

```java
数据类型 变量名;              // 只声明，不赋值
数据类型 变量名 = 值;         // 声明的同时初始化
```

```java
int age;                    // 声明
age = 20;                   // 赋值
int score = 95;             // 声明并初始化（推荐）
```

**Java 是强类型语言**。这是本课时的核心概念，含义是：

1. **每个变量必须先声明类型才能使用**，且类型一旦确定就不能改变
2. **赋值时类型必须兼容**，否则编译期直接报错
3. 类型检查发生在**编译期**，而不是运行期

```java
int a = 10;
a = "abc";              // ❌ 编译错误：不兼容的类型，String 无法转换为 int

int b;
System.out.println(b);  // ❌ 编译错误：可能尚未初始化变量 b
```

**强类型 vs 弱类型对比**：

| | Java（强类型） | JavaScript / Python（弱类型 / 动态类型） |
|---|---|---|
| 声明 | `int a = 10;` 必须写类型 | `let a = 10` / `a = 10` |
| 改变类型 | 不允许 | `a = "abc"` 完全合法 |
| 错误发现时机 | **编译期** | 运行期（可能上线后才炸） |
| 优点 | 安全、IDE 提示准确、重构可靠 | 灵活、代码简洁 |

强类型的价值在于**把错误提前到编译期**。一个类型写错的 bug，Java 在你按下保存的瞬间就标红了，而弱类型语言可能要等到线上用户触发才暴露。

**同行声明方式**（同一类型的多个变量可以写在一行，用逗号分隔）：

```java
int a, b, c;                    // 同时声明三个 int
int x = 1, y = 2, z = 3;        // 声明并分别初始化
int m = 1, n;                   // 混合：m 初始化，n 只声明
```

**注意事项**：

```java
int a = b = c = 10;     // ❌ 报错：b、c 未声明
int a, b, c;
a = b = c = 10;         // ✅ 合法：连续赋值，从右向左执行
```

**同行声明的实践建议**：阿里巴巴开发手册**不推荐**在一行声明多个变量 —— 可读性差，且不方便给每个变量单独写注释。除非是关系极其紧密的变量（如循环里的 `int i, j`），否则建议一行一个。

**`var` 关键字（JDK 10+ 的局部变量类型推断）**：

```java
var name = "张三";                       // 编译器推断为 String
var list = new ArrayList<String>();      // 推断为 ArrayList<String>
var count = 10;                          // 推断为 int
```

**`var` 不是弱类型**！它只是让编译器**自动推断**类型，变量类型在编译后依然是固定的，仍然是强类型。限制条件：

- 只能用于**局部变量**（方法内部），不能用于成员变量、方法参数、返回值
- **必须初始化**（否则无从推断）：`var a;` 报错
- 不能赋 `null`：`var a = null;` 报错

使用建议：右侧类型显而易见时用 `var` 能减少冗余（如 `var map = new HashMap<String, List<User>>();`）；类型不明显时（如 `var result = service.process();`）反而降低可读性，应写出完整类型。

## 4.2 变量的赋值方式

**本课时对应知识点**：变量的赋值方式、多次赋值会产生覆盖效果。

**赋值运算符 `=`**。注意：Java 中 `=` 是**赋值**，不是数学上的「等于」。判断相等要用 `==`。

```java
int a = 10;     // 把 10 存入 a 的内存空间
a = 20;         // 用 20 覆盖原来的 10，原值永久丢失
```

**赋值的方向：从右向左**。先计算右边的表达式，再把结果存入左边的变量。

```java
int a = 1 + 2 * 3;      // 先算右边得 7，再赋给 a
int b = a;              // 把 a 的值（7）复制一份给 b
```

**多次赋值的覆盖效果**：

```java
int score = 60;
System.out.println(score);   // 60
score = 80;
System.out.println(score);   // 80，60 已经被彻底覆盖
score = 95;
System.out.println(score);   // 95
```

变量的名字来源就在这里 —— 值是**可变**的。这与常量（`final`，见 3.1 课时）形成对照。

**变量之间赋值是「值的复制」，不是「绑定」**：

```java
int a = 10;
int b = a;      // 把 a 的值复制给 b，此后两者再无关系
a = 20;
System.out.println(b);   // 10（不是 20！b 不会跟着变）
```

**但引用类型的赋值复制的是「地址」**（重要区别，见 JB1-2 第 6 单元）：

```java
int[] arr1 = {1, 2, 3};
int[] arr2 = arr1;       // 复制的是地址，两个变量指向同一个数组对象
arr1[0] = 100;
System.out.println(arr2[0]);   // 100（跟着变了！因为是同一个数组）
```

**连续赋值（从右向左结合）**：

```java
int a, b, c;
a = b = c = 10;         // 先 c=10，再 b=c，最后 a=b，三个都是 10
```

**复合赋值运算符**（详见第 7 单元）：

```java
int a = 10;
a += 5;    // 等价于 a = a + 5;    → 15
a -= 3;    // 等价于 a = a - 3;    → 12
a *= 2;    // 等价于 a = a * 2;    → 24
a /= 4;    // 等价于 a = a / 4;    → 6
a %= 4;    // 等价于 a = a % 4;    → 2
```

**复合赋值运算符隐含强制类型转换（考点）**：

```java
byte b = 10;
b = b + 5;      // ❌ 编译错误：b+5 的结果是 int，不能直接赋给 byte
b += 5;         // ✅ 合法！等价于 b = (byte)(b + 5)，编译器自动加了强转
```

这是一个非常经典的面试题。原因是复合赋值运算符在语言规范中被定义为自带隐式强转。

**变量的作用域（Scope）**。变量只在它所在的 `{}` 代码块内有效，出了大括号就被销毁：

```java
public void test() {
    int a = 10;
    if (true) {
        int b = 20;
        System.out.println(a);   // ✅ 内层能访问外层
    }
    System.out.println(b);       // ❌ 编译错误：b 的作用域已结束
}
```

**变量的分类**：

| 类型 | 位置 | 默认值 | 生命周期 |
|---|---|---|---|
| **局部变量** | 方法内 | **无默认值，必须手动初始化** | 方法执行期间 |
| **成员变量**（实例变量） | 类内方法外 | 有默认值（int→0, boolean→false, 引用→null） | 对象存在期间 |
| **静态变量**（类变量） | 类内，加 `static` | 有默认值 | 类加载到卸载 |

```java
public class Demo {
    int instanceVar;             // 成员变量，默认 0
    static int staticVar;        // 静态变量，默认 0

    public void method() {
        int localVar;            // 局部变量，无默认值
        System.out.println(instanceVar);   // ✅ 0
        System.out.println(localVar);      // ❌ 编译错误：可能尚未初始化
    }
}
```

**为什么局部变量没有默认值**：局部变量在**栈**上分配，方法调用极其频繁，如果每次都清零会有性能开销；而成员变量在**堆**上分配，JVM 在分配对象内存时会统一清零。这个设计也强制程序员显式初始化，减少「忘记赋值」的隐蔽 bug。

## 4.3 变量的命名规范

**本课时对应知识点**：变量名的硬性要求、变量名的软性要求。

**硬性要求（违反直接编译报错）**：

1. **只能由字母、数字、下划线 `_`、美元符 `$` 组成**（这里的「字母」包括 Unicode 字母，所以中文变量名在语法上合法，但绝不要用）
2. **不能以数字开头**
3. **不能是关键字或保留字**
4. **严格区分大小写**（`age` 和 `Age` 是两个不同的变量）

```java
int age;        // ✅
int _count;     // ✅（合法但不推荐）
int $price;     // ✅（合法但不推荐，$ 通常用于编译器生成的名字）
int age2;       // ✅
int 年龄;        // ✅ 语法合法，但❌ 绝对不要这样写

int 2age;       // ❌ 数字开头
int my-age;     // ❌ 含有连字符
int my age;     // ❌ 含有空格
int class;      // ❌ class 是关键字
int int;        // ❌ 关键字
```

**Java 关键字（不能作为变量名）**：

```
abstract  assert    boolean   break     byte      case      catch     char
class     const     continue  default   do        double    else      enum
extends   final     finally   float     for       goto      if        implements
import    instanceof int      interface long      native    new       package
private   protected public    return    short     static    strictfp  super
switch    synchronized this   throw     throws    transient try       void
volatile  while
```

另外 `true`、`false`、`null` 是**字面量**（不是关键字，但同样不能作为变量名）。`var`、`record`、`sealed`、`yield` 是**上下文关键字**，在特定位置有特殊含义。

**软性要求（不违反会编译通过，但会被同事和 Code Review 批评）**：

**① 见名知意** —— 最重要的一条：

```java
int a;                  // ❌ 完全看不出用途
int userAge;            // ✅

String s;               // ❌
String userName;        // ✅

List<User> list;        // ❌ 太笼统
List<User> activeUsers; // ✅
```

**② 使用小驼峰命名（lowerCamelCase）** —— 第一个单词全小写，后续单词首字母大写：

```java
int userAge;
String orderNumber;
boolean isDeleted;
double totalPrice;
```

**③ 布尔变量用 `is` / `has` / `can` 开头**：

```java
boolean isValid;
boolean hasPermission;
boolean canDelete;
```

> ⚠️ 阿里手册规定：**POJO 类中的布尔变量不要加 `is` 前缀**（写 `deleted` 而非 `isDeleted`），因为某些序列化框架会解析出 `getDeleted()` 和 `isDeleted()` 两个方法而产生歧义。局部变量则不受此限。

**④ 集合类变量用复数或加后缀**：

```java
List<User> users;          // 复数
List<User> userList;       // 加类型后缀
Map<Long, User> userMap;
```

**⑤ 避免容易混淆的字符**：不要用单独的 `l`（易与 `1` 混）、`O`（易与 `0` 混）、`I`（易与 `l` 混）作变量名。

**⑥ 循环变量可以短**。`i`、`j`、`k` 作为循环计数器是全世界通用的约定，不需要改成 `index`。这属于「上下文已经足够清晰」的例外。

**⑦ 不要用拼音，也不要中英混杂**：

```java
int nianLing;          // ❌ 拼音
int age;               // ✅

String userMingCheng;  // ❌ 中英混杂
String userName;       // ✅
```

例外：国内特有的业务概念用拼音反而更准确，如 `hukou`（户口）、`chengguan`（城管）—— 这些没有公认的英文对应词。

**⑧ 命名长度适中**。太短看不懂，太长影响阅读。作用域越大，名字应该越具体；作用域越小（如三行的循环体内），名字可以越短。

**各类标识符命名规范汇总**：

| 类型 | 规范 | 示例 |
|---|---|---|
| 包 | 全小写，点分隔 | `com.mdkj.service` |
| 类 / 接口 | 大驼峰 | `UserService` |
| 方法 | 小驼峰，动词开头 | `getUserById` |
| 变量 | 小驼峰 | `userName` |
| 常量 | 全大写，下划线分隔 | `MAX_SIZE` |
| 抽象类 | `Abstract` 或 `Base` 前缀 | `AbstractService` |
| 异常类 | `Exception` 后缀 | `BusinessException` |
| 测试类 | `Test` 后缀 | `UserServiceTest` |

## 4.4 代码的整洁之道

**本课时对应知识点**：代码沼泽困境、保证代码整洁的经验之谈。

**什么是「代码沼泽」**。项目初期代码清爽，随着需求不断叠加、赶工期不断妥协，代码逐渐变成一片沼泽：改一处就崩另一处、没人敢删任何代码、新人接手要看两周、修一个 bug 引入三个新 bug。

**代码沼泽的典型症状**：

1. **超长方法** —— 一个方法几百上千行，需要滚动好几屏才能看完
2. **深层嵌套** —— `if` 套 `if` 套 `for` 套 `try`，缩进到屏幕右半边
3. **魔法数字** —— `if (type == 3 && status == 7)`，没人知道 3 和 7 是什么
4. **重复代码** —— 同一段逻辑复制粘贴到十几处，改的时候漏掉几处
5. **命名随意** —— `a`、`temp`、`data`、`obj`、`flag2`
6. **注释与代码不符** —— 注释说的是三个版本之前的逻辑
7. **死代码** —— 大段被注释掉的代码，或永远走不到的分支
8. **上帝类** —— 一个类几千行，什么都干

**保证代码整洁的经验之谈**：

**① 一个方法只做一件事**。方法体尽量控制在一屏内（20–50 行）。超过就该拆分 —— IDEA 快捷键 `Ctrl + Alt + M` 可以一键抽取方法。

```java
// ❌ 一个方法干了三件事
public void handleOrder(Order order) {
    // 50 行校验参数
    // 80 行计算价格
    // 60 行发送通知
}

// ✅ 拆分后主流程一目了然
public void handleOrder(Order order) {
    validate(order);
    calculatePrice(order);
    sendNotification(order);
}
```

**② 用卫语句（Guard Clause）减少嵌套**。这是消除深层缩进最有效的技巧：

```java
// ❌ 嵌套四层，读到最里面已经忘了外面的条件
public void process(User user) {
    if (user != null) {
        if (user.isActive()) {
            if (user.hasPermission()) {
                // 真正的业务逻辑
            }
        }
    }
}

// ✅ 卫语句：不满足条件立即返回，主逻辑保持在最外层
public void process(User user) {
    if (user == null) return;
    if (!user.isActive()) return;
    if (!user.hasPermission()) return;

    // 真正的业务逻辑，没有任何缩进
}
```

**③ 消灭魔法数字，用常量或枚举**：

```java
// ❌
if (status == 3) { ... }

// ✅ 常量
private static final int ORDER_CANCELLED = 3;
if (status == ORDER_CANCELLED) { ... }

// ✅✅ 枚举更好（见 JB1-3 特殊之枚举类）
if (status == OrderStatus.CANCELLED) { ... }
```

**④ 消除重复（DRY 原则：Don't Repeat Yourself）**。同样的逻辑出现第三次时，一定要抽成方法或工具类。重复代码的真正危害不是「多打了字」，而是**修改时必然会漏掉某一处**。

**⑤ 及时删除死代码**。有 Git 管着历史，注释掉的代码直接删。留着它们只会让人困惑「这段还要不要用」。

**⑥ 保持一致的代码风格**。团队统一缩进、括号位置、命名习惯。用 IDEA 的 `Ctrl + Alt + L` 格式化，配合 `.editorconfig` 或统一的 Code Style 配置文件。

**⑦ 变量声明靠近使用处**。不要在方法开头声明一堆变量再到几十行后才用 —— 那是 C89 的历史遗留习惯。

**⑧ 尽早返回，尽早抛异常**。让错误在最接近发生点的地方暴露，而不是层层传递到很远的地方才崩溃。

**⑨ 写代码时想着「三个月后的自己」**。你会忘记今天所有的上下文。代码是写给人读的，机器只是顺便执行一下。

**⑩ 用工具兜底**。IDEA 内置 Inspection 检查、装 Alibaba Java Coding Guidelines 插件（见 JB1-1 第 3 单元）、项目里接入 SonarQube 或 Checkstyle。**让机器来提醒你，比靠自觉可靠得多**。

**关于重构的时机**：不要等到「有空了再重构」—— 那一天永远不会来。正确的做法是**童子军规则**：每次修改一个文件时，让它比你来时**稍微干净一点点**。改个 bug 顺手改好一个变量名，加个功能顺手抽出一个重复方法。持续的小改进，比一次性的大重构安全得多，也现实得多。
