## 1.1 代码的基本注释

**本课时对应知识点**：单行注释、多行注释、文档注释、TODO 注释。

**注释是什么**。注释是写给**人**看的说明文字，编译器会完全忽略它们（`javac` 在词法分析阶段就把注释丢弃了，不会进入字节码）。所以注释再多也不影响程序运行效率和 class 文件大小。

**三种注释形式**：

```java
// 单行注释：从 // 到本行结束

/*
   多行注释
   可以跨越多行
   常用于方法内部的成段说明
*/

/**
 * 文档注释（javadoc 注释）
 * 可以被 javadoc 工具提取成 HTML API 文档
 * 只能写在类、接口、字段、方法、构造器之前
 */
```

**实际用法示例**：

```java
public class UserService {

    // 单行注释：说明这一行在做什么
    private static final int MAX_RETRY = 3;

    /*
     * 多行注释：解释一段复杂逻辑的整体思路
     * 这里采用双重校验锁实现单例，
     * volatile 是为了防止指令重排序
     */
    private static volatile UserService instance;

    /**
     * 文档注释：会出现在生成的 API 文档中
     *
     * @param id 用户主键
     * @return 用户对象，不存在时返回 null
     */
    public User getById(Long id) {
        // TODO: 待补充缓存逻辑
        // FIXME: id 为负数时未做校验
        return null;
    }
}
```

**TODO 与 FIXME 注释**。这是团队约定的**特殊标记**，IDE 会识别并汇总：

| 标记 | 含义 |
|---|---|
| `TODO` | 待办事项，功能还没做完 |
| `FIXME` | 已知缺陷，需要修复 |
| `XXX` | 有问题的实现，需要重构 |
| `HACK` | 临时的权宜之计 |

在 IDEA 中：底部 `TODO` 窗口（或 `View → Tool Windows → TODO`）会列出整个项目的所有标记，双击直接跳转。可以在 `Settings → Editor → TODO` 中自定义模式和高亮颜色。

**注释的实践原则（比语法更重要）**：

1. **解释「为什么」，而不是「是什么」**。代码本身已经说清了「是什么」：

```java
i++;                    // ❌ 无用注释：i 自增 1
i++;                    // ✅ 有用注释：跳过表头行
```

2. **复杂业务规则必须注释**。魔法数字、特殊算法、绕开某个 bug 的临时方案，不写注释后人无法理解：

```java
// 秒杀库存扣减必须用 Lua 脚本，保证「判断 + 扣减」的原子性，
// 分开写会在高并发下超卖
```

3. **注释必须与代码同步更新**。**过时的注释比没有注释更糟糕** —— 它会主动误导读者。改代码时一定要检查相关注释。

4. **不要注释掉代码后留在那里**。有 Git 管着历史，直接删掉。大段被注释的死代码是项目腐化的典型标志。

5. **好的命名可以减少注释需求**。`int d;` 需要注释，`int daysSinceCreated;` 不需要。

## 1.2 产品的文档注释

**本课时对应知识点**：文档注释的意义与优点、常用注解标签、提取 HTML 文档的方式。

**文档注释的意义**。当你写一个工具类、SDK 或对外接口给别人用时，对方不应该被迫去读你的源码。文档注释让**注释和代码写在一起**（永远不会分家），又能**自动导出成独立的 HTML 文档**供他人查阅。JDK 自带的 API 文档就是这样生成的 —— 你查 `String.substring()` 时看到的说明，就来自 JDK 源码里的文档注释。

**优点总结**：与代码同源，改代码顺手改文档；IDE 能识别，鼠标悬停在方法上直接显示说明（`Ctrl + Q` 查看）；可一键生成标准 HTML 文档；团队协作时降低沟通成本。

**常用文档注解标签**：

| 标签 | 用途 | 示例 |
|---|---|---|
| `@author` | 作者 | `@author 刘能` |
| `@version` | 版本号 | `@version 1.0` |
| `@since` | 从哪个版本开始有 | `@since 1.8` |
| `@param` | 方法参数说明 | `@param id 用户主键` |
| `@return` | 返回值说明 | `@return 用户对象` |
| `@throws` / `@exception` | 可能抛出的异常 | `@throws IOException 文件不存在时` |
| `@see` | 参考其他类或方法 | `@see UserMapper#selectById` |
| `@link` | 行内链接 | `{@link User}` |
| `@code` | 行内代码格式 | `{@code List<String>}` |
| `@deprecated` | 标记已过时 | `@deprecated 请改用 getByIdV2()` |

**完整示例**：

```java
package com.mdkj.util;

/**
 * 字符串处理工具类。
 * <p>
 * 提供空值判断、驼峰下划线互转等常用操作，所有方法均为静态方法。
 *
 * @author 刘能
 * @version 1.0
 * @since 2026-09-01
 */
public class StringUtil {

    /**
     * 判断字符串是否为空。
     * <p>
     * 空的定义：{@code null}、长度为 0、或仅由空白字符组成。
     *
     * @param str 待判断的字符串，允许为 {@code null}
     * @return 为空返回 {@code true}，否则返回 {@code false}
     * @see #isNotBlank(String)
     */
    public static boolean isBlank(String str) {
        return str == null || str.trim().isEmpty();
    }

    /**
     * 截取字符串。
     *
     * @param str   源字符串
     * @param start 起始下标，从 0 开始
     * @param end   结束下标，不包含
     * @return 截取后的子串
     * @throws StringIndexOutOfBoundsException 下标越界时抛出
     * @deprecated 语义不清晰，请改用 {@link #sub(String, int, int)}
     */
    @Deprecated
    public static String substring(String str, int start, int end) {
        return str.substring(start, end);
    }
}
```

**书写规范**：第一句话是**摘要**（会显示在方法列表中），应当独立成句并以句号结尾；`@param` 的顺序要与方法参数顺序一致；每个参数、返回值、可能的异常都要写；HTML 标签可以直接用（`<p>` 分段、`<ul><li>` 列表、`<pre>` 保留格式）。

**提取 HTML 文档的三种方式**：

**① 命令行 javadoc 工具**：

```bash
# 基本用法
javadoc -d doc StringUtil.java

# 中文项目必须指定编码，否则乱码
javadoc -encoding UTF-8 -charset UTF-8 -d doc StringUtil.java

# 生成整个包的文档
javadoc -encoding UTF-8 -charset UTF-8 -d doc -sourcepath src com.mdkj.util
```

`-d doc` 表示输出到 `doc` 目录，生成后打开其中的 `index.html` 即可浏览。

**② IDEA 图形化生成**：`Tools → Generate JavaDoc`，指定输出目录，在 `Other command line arguments` 里填 `-encoding UTF-8 -charset UTF-8`（中文项目必填），点 OK。

**③ Maven 插件（项目中最常用）**：

```xml
<build>
    <plugins>
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-javadoc-plugin</artifactId>
            <version>3.6.3</version>
            <configuration>
                <encoding>UTF-8</encoding>
                <charset>UTF-8</charset>
                <docencoding>UTF-8</docencoding>
                <!-- JDK 8+ 的 doclint 检查非常严格，注释不规范会直接构建失败 -->
                <doclint>none</doclint>
            </configuration>
        </plugin>
    </plugins>
</build>
```

执行 `mvn javadoc:javadoc` 生成文档，`mvn javadoc:jar` 打成 jar 包（发布到 Maven 中央仓库时是必需的）。

**三个高频问题**：

| 问题 | 原因与解决 |
|---|---|
| 生成的 HTML 中文乱码 | 没加 `-encoding UTF-8 -charset UTF-8` |
| `错误: 编码 GBK 的不可映射字符` | 同上，Windows 默认 GBK |
| doclint 报错导致构建失败 | JDK 8+ 会严格校验 javadoc 语法（如 `@param` 与参数不匹配、HTML 标签未闭合）。规范注释，或临时加 `-Xdoclint:none` |

**与接口文档工具的关系**。企业开发中，对外的 **HTTP 接口**文档通常不用 javadoc，而是用 **Knife4j / Swagger（OpenAPI）** —— 它们通过 `@Operation`、`@Schema` 等注解生成可在线调试的接口页面。javadoc 面向的是**类和方法级别的 Java API**，两者用途不同、可以共存。本平台（知堂课堂）用的就是 Knife4j。
