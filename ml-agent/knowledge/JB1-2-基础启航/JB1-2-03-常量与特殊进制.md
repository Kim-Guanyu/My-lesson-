## 3.1 先天与后天常量

**本课时对应知识点**：先天常量、后天常量、`final` 关键字、科学计数法。

**常量的定义**：值在程序运行期间**不能改变**的量。Java 中的常量分两类：

**先天常量（字面量 / 字面常量）** —— 直接写在代码里的值，天生不可改变：

```java
100          // 整数字面量
3.14         // 浮点字面量
'A'          // 字符字面量
"Hello"      // 字符串字面量
true         // 布尔字面量
null         // 空字面量
```

**后天常量（用 `final` 修饰的变量）** —— 本来是变量，被 `final` 修饰后变成常量：

```java
final int MAX_SIZE = 100;
MAX_SIZE = 200;    // ❌ 编译错误：cannot assign a value to final variable
```

**`final` 关键字的三种用法**（面试常问）：

| 修饰对象 | 含义 |
|---|---|
| **修饰变量** | 值不可改变（基本类型值不变，引用类型**引用地址**不变） |
| **修饰方法** | 不可被子类重写（override）—— 见 JB1-3 多态机制 |
| **修饰类** | 不可被继承，如 `String`、`Integer` 都是 final 类 |

**`final` 修饰引用类型的重要细节**：

```java
final int[] arr = {1, 2, 3};
arr[0] = 100;              // ✅ 允许：改的是数组内容
arr = new int[]{4, 5, 6};  // ❌ 报错：改的是引用指向

final User user = new User();
user.setName("张三");       // ✅ 允许：改的是对象内部状态
user = new User();          // ❌ 报错：改的是引用指向
```

**记忆要点**：`final` 锁的是「**变量本身存的那个值**」。对基本类型来说存的是数值，所以数值不能变；对引用类型来说存的是**地址**，所以地址不能变，但地址指向的对象内容可以变。

**常量命名规范**：**全大写，单词间用下划线分隔**：

```java
final int MAX_RETRY_COUNT = 3;
final double PI = 3.14159;
final String DEFAULT_ENCODING = "UTF-8";
```

**静态常量（类常量）**。加上 `static` 后属于类而非对象，全局唯一、只初始化一次：

```java
public class Constants {
    public static final int PAGE_SIZE = 10;
    public static final String SUCCESS_CODE = "1000";
}
// 使用：Constants.PAGE_SIZE
```

`public static final` 是定义全局常量的标准写法。本平台（知堂课堂）的 `ml-common` 模块里就有这样一个常量类 `ML`。

**用常量替代「魔法数字」**。直接在代码里写字面量叫魔法数字，可读性和可维护性都很差：

```java
if (status == 3) { ... }                    // ❌ 3 是什么意思？
if (status == ORDER_CANCELLED) { ... }      // ✅ 一眼看懂
```

**科学计数法**。表示很大或很小的数：

```java
double d1 = 1.5e3;     // 1.5 × 10³  = 1500.0
double d2 = 1.5E3;     // 大小写 e 都可以
double d3 = 2.5e-4;    // 2.5 × 10⁻⁴ = 0.00025
double d4 = 1e8;       // 100000000.0
```

**注意：带 e 的字面量一定是浮点类型**，所以 `int a = 1e2;` 会编译报错（需要 `(int)1e2` 强转）。

**数字字面量中的下划线（JDK 7+）**。提升长数字的可读性，编译时会被忽略：

```java
int million = 1_000_000;            // 等价于 1000000
long card = 6222_0202_0000_1234L;   // 银行卡号分组
int binary = 0b1010_1010;           // 二进制分组
```

规则：下划线只能夹在**数字之间**，不能放在开头、结尾、小数点旁边或后缀字母旁。

**字面量的默认类型（重要考点）**：

```java
100        // 默认 int
100L       // long（后缀 L 或 l，推荐大写 L，小写 l 容易和数字 1 混淆）
3.14       // 默认 double
3.14F      // float（后缀 F 或 f）
'A'        // char
"A"        // String
```

由此产生两个常见错误：

```java
long big = 10000000000;      // ❌ 报错：字面量默认是 int，超出 int 范围
long big = 10000000000L;     // ✅ 加 L 后缀

float f = 3.14;              // ❌ 报错：3.14 默认是 double，不能自动转 float
float f = 3.14F;             // ✅ 加 F 后缀
```

## 3.2 特殊进制的常量

**本课时对应知识点**：二进制、八进制、十六进制的表现形式。

**Java 支持四种进制的整数字面量**：

| 进制 | 前缀 | 数码范围 | 示例 | 十进制值 |
|---|---|---|---|---|
| 十进制 | 无 | 0–9 | `100` | 100 |
| **二进制** | `0b` 或 `0B` | 0–1 | `0b1100100` | 100 |
| **八进制** | `0`（数字零） | 0–7 | `0144` | 100 |
| **十六进制** | `0x` 或 `0X` | 0–9, A–F | `0x64` | 100 |

```java
int a = 100;           // 十进制
int b = 0b1100100;     // 二进制（JDK 7+ 支持）
int c = 0144;          // 八进制
int d = 0x64;          // 十六进制
System.out.println(a == b && b == c && c == d);   // true，四个值完全相同
```

> ⚠️ **八进制的陷阱**：以 `0` 开头的数字会被当作八进制！`int x = 0100;` 的值是 **64** 而不是 100。写日期、编号时如果不小心写成 `08` 或 `09` 会直接编译报错（8 和 9 不是合法的八进制数码）。

**进制转换（无论输出还是解析，都用 Integer 的静态方法）**：

```java
// 十进制 → 其他进制（返回 String）
System.out.println(Integer.toBinaryString(100));   // 1100100
System.out.println(Integer.toOctalString(100));    // 144
System.out.println(Integer.toHexString(100));      // 64
System.out.println(Integer.toString(100, 2));      // 1100100（任意进制，2~36）

// 其他进制字符串 → 十进制
System.out.println(Integer.parseInt("1100100", 2));  // 100
System.out.println(Integer.parseInt("144", 8));      // 100
System.out.println(Integer.parseInt("64", 16));      // 100
```

**手工换算方法**：

**其他进制 → 十进制：按权展开**

```
二进制 1100100
= 1×2⁶ + 1×2⁵ + 0×2⁴ + 0×2³ + 1×2² + 0×2¹ + 0×2⁰
= 64 + 32 + 0 + 0 + 4 + 0 + 0
= 100
```

**十进制 → 其他进制：除基取余，逆序排列**

```
100 ÷ 2 = 50 余 0  ↑
 50 ÷ 2 = 25 余 0  │
 25 ÷ 2 = 12 余 1  │  从下往上读
 12 ÷ 2 =  6 余 0  │
  6 ÷ 2 =  3 余 0  │
  3 ÷ 2 =  1 余 1  │
  1 ÷ 2 =  0 余 1  │
结果：1100100
```

**二进制与十六进制的快速互转（实用技巧）**。因为 16 = 2⁴，所以**每 4 位二进制 = 1 位十六进制**：

```
二进制  1100 0100
         ↓    ↓
十六进制  C    4     →  0xC4
```

这也是为什么程序员偏爱十六进制 —— 它是二进制的紧凑写法，转换心算即可完成。

**十六进制的实际应用场景**：

```java
int color = 0xFF5733;                 // RGB 颜色值
int mask  = 0xFF;                     // 位掩码，取低 8 位
byte[] md5 = ...;                     // MD5、SHA 等哈希值通常用十六进制展示
System.out.println(Integer.toHexString(hashCode()));  // 对象哈希码
```

`System.out.println(new Object())` 输出的 `java.lang.Object@1b6d3586` 中，`@` 后面就是十六进制的哈希码。

**为什么计算机用二进制**：电子元件最容易实现两种稳定状态（高电平 / 低电平、有电 / 无电、导通 / 截止），用二进制表示最可靠、成本最低、抗干扰能力最强。八进制和十六进制则是为了让**人**读写二进制更方便而生的中间形式。

## 3.3 计算机计算原理

**本课时对应知识点**：原码、反码、补码、真值、`Integer.toBinaryString()`。

**核心问题**：计算机怎么表示负数？怎么做减法？

计算机内部只有 0 和 1，没有「负号」这个符号。解决办法是**拿出最高位当符号位**：0 表示正数，1 表示负数。剩下的位表示数值。

**三种编码（以 8 位为例说明，Java 的 int 是 32 位）**：

**原码** —— 最直观：符号位 + 数值的绝对值的二进制。

```
+5 的原码：0000 0101
-5 的原码：1000 0101      （最高位 1 表示负）
```

**原码的致命问题**：直接相加得不到正确结果。

```
  5 + (-5)
= 0000 0101 + 1000 0101
= 1000 1010
= -10                    ❌ 应该是 0
```

另外原码里 `0000 0000`（+0）和 `1000 0000`（−0）表示了两个零，浪费且混乱。

**反码** —— 正数的反码是自身；负数的反码是原码**符号位不变，其余位取反**。

```
+5 的反码：0000 0101      （与原码相同）
-5 的反码：1111 1010      （符号位保持1，其余取反）
```

反码相加接近正确，但仍有「循环进位」和「双零」问题。

**补码（计算机实际使用的编码）** —— 正数的补码是自身；负数的补码是**反码 + 1**。

```
-5 的原码：1000 0101
-5 的反码：1111 1010      （符号位不变，其余取反）
-5 的补码：1111 1011      （反码 + 1）
```

**验证补码的正确性**：

```
  5 + (-5)
= 0000 0101 + 1111 1011
= 1 0000 0000            （最高位溢出被丢弃）
= 0000 0000
= 0                      ✅ 正确！
```

**补码的三大优势（面试重点）**：

1. **符号位可以直接参与运算**，不需要单独处理
2. **减法可以转化成加法**：`a - b = a + (-b)`，CPU 只需要实现加法器，硬件大幅简化
3. **零的表示唯一**：只有 `0000 0000` 一个零，多出的 `1000 0000` 被用来表示 −128，所以 byte 的范围是 **−128 ~ 127**（负数比正数多一个）

**「真值」的概念** —— 编码所代表的、带符号的实际数值。补码 `1111 1011` 的真值是 −5。

**由补码反推真值**：对补码再做一次「取反加一」，得到的就是绝对值。

```
补码：      1111 1011
取反：      0000 0100
加一：      0000 0101  = 5
最高位是1 → 真值 = -5
```

**用 `Integer.toBinaryString()` 观察补码**：

```java
System.out.println(Integer.toBinaryString(5));
// 101（前导 0 被省略，完整是 00000000000000000000000000000101）

System.out.println(Integer.toBinaryString(-5));
// 11111111111111111111111111111011   ← 32 位补码，全部显示出来了

System.out.println(Integer.toBinaryString(-1));
// 11111111111111111111111111111111   ← -1 的补码是全 1，很好记

System.out.println(Integer.toBinaryString(Integer.MIN_VALUE));
// 10000000000000000000000000000000   ← 最小值只有符号位是 1
```

**注意**：`toBinaryString()` 对正数会省略前导 0，对负数则显示完整 32 位（因为最高位是 1，无法省略）。

**用补码解释「最大值 +1 变最小值」**（与 5.7 课时呼应）：

```
Integer.MAX_VALUE  = 0111 1111 ... 1111  (2147483647)
              + 1  = 1000 0000 ... 0000  (符号位被进位改成了 1)
                   = Integer.MIN_VALUE   (-2147483648)
```

数值溢出后从最大跳到最小，本质是符号位被进位「污染」了。这也解释了为什么整数范围在数轴上是**首尾相接的环形**。

**补码在位运算中的体现**（预告 JB1-2 第 7 单元）：

```java
System.out.println(-5 >> 1);    // -3   算术右移，高位补符号位 1
System.out.println(-5 >>> 1);   // 2147483645  无符号右移，高位补 0
System.out.println(~5);         // -6   按位取反，等价于 -(n+1)
```

`~n == -(n+1)` 这个规律正是补码定义的直接推论：`-n` 的补码 = `~n + 1`，移项即得。

**范围记忆**：n 位有符号整数的范围是 **−2ⁿ⁻¹ ~ 2ⁿ⁻¹−1**。所以 byte（8 位）是 −128~127，short（16 位）是 −32768~32767，int（32 位）是 −2147483648~2147483647。
